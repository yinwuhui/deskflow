# 06 跨平台与系统集成

版本 v1.0 开发基线；授权与实现证据见 [决策记录](10_整体确认清单与决策记录.md)。下表是设计要求和能力检查方向；不构成真实桌面环境验证结果。

## 共享代码与平台适配

现有 GUI 主要是 C++ / Qt Widgets 与 `.ui`，使用共享配置／核心进程包装；输入、权限与系统入口有平台差异。建议继续共享信息架构、状态模型和业务流程，把系统差异收敛到能力适配层。Qt 标准控件按系统渲染，避免三套互不一致的状态逻辑。

## macOS 规则

关闭窗口与退出应用分离。关闭时可隐藏到菜单栏；Cmd+Q、Apple 菜单和 Dock 的退出是明确退出，不能被“关闭到托盘”偏好吞掉。当前 `MainWindow.cpp` 的 native quit handler 路由到 hide-to-tray，属于需修正的行为差异。入口权限检查失败目前可能在主界面前结束；新设计需要可恢复设置／诊断页面。

系统权限按钮打开对应指引／设置，返回后重测；不以点击授权按钮作为成功。菜单栏图标不是进程是否运行的唯一证明；用户关闭图标或权限不足要有返回路径。真正的隐私授权名称随安装包签名和系统能力核验后确定。

## Windows 规则

服务选项仅在已安装的非便携版本中显示可启用控件，实际安装、运行、权限、停止确认分别检测。普通桌面进程与后台服务不能混淆，提升后台权限时说明用途。

- 停止共享并退出：发出服务／进程停止请求 → 收到停止确认 → 关闭界面；超时或失败保留界面和重试／检查入口。
- 仅退出界面（共享继续）：仅在明确检测服务已运行且用户主动选择时提供；持续说明输入共享会继续。
- 关闭窗口：依据偏好隐藏／走明确退出逻辑；不能把任何退出都解释成隐藏。

现有 `CoreProcess::cleanup()` 只在 Desktop 模式停止核心，服务模式 UI 结束不能证明共享停止。工程必须补齐停止确认和服务状态读取，而非只修改按钮名称。

## X11、Wayland 与无托盘环境

无托盘／菜单扩展时不隐藏到不可返回状态；最小化或保持窗口可见，主动退出仍可用。X11 修复按目标电脑能力显示；未知目标不能被自动写成关闭已有选项。Wayland 输入、全局快捷键和授权恢复使用真实后端反馈，授权被撤销时立刻反映，不重试弹窗轰炸或自动绕过。

## 生命周期与通知

睡眠、唤醒、网络切换、屏幕锁定和用户暂停分别记录。用户暂停在唤醒后保持；网络恢复仅允许符合信任与安全策略的重新连接。系统关机／注销不被 UI 的草稿或普通确认弹窗阻塞，按平台支持尽力保存 UI 草稿，不执行额外本机命令。

通知允许与否不影响核心连接。前台用横幅，后台对身份变化、重要掉线、服务故障按 episode 去重通知；静默的正常重试不重复提醒。点击通知打开真实对象页面，不直接接受身份或启用兼容降级。已有托盘未读标记保留直到问题解决或明确处理。

## 需要实机交付证据

每个平台分别验证安装形态、权限初次／拒绝／撤销、托盘存在／缺失、关闭／明确退出、睡眠恢复、语言切换、DPI、读屏与系统快捷键。Wayland 至少按项目实际支持的桌面／组合器及 Portal 版本记录；支持名单在产品实现阶段实测后发布，不以本原型矩阵代替。
