## 本版整合决定（拟冻结）

| 决策 | 理由 / 替代的早期简化 |
|---|---|
| 完整多行多列画布是主能力，四方向只是新设备快捷摆放 | 避免丢失既有100×100布局与复杂切换路径 |
| 接收端不虚构完整拓扑，本地输入选项可写 | 来源管理布局不等于来源管理接收端全部设置 |
| 延迟与双触独立，规则支持全动作与按下／释放 | 保留当前配置表达能力 |
| 显示名／稳定ID拟分离，名称迁移仍遵循旧规则 | 避免重命名破坏链接、别名与动作引用 |
| 配置有草稿／保存／生效版本 | 防止保存即中断和应用即连接的假成功 |
| 明确退出与窗口关闭分离 | 修正CmdQ转隐藏及服务GUI退出不停止的歧义 |
| 逐设备信任与本机身份分别管理 | 本机换证不应清掉独立的远端信任 |
| 所有系统能力显示检测结果和未知状态 | 不把平台名称当支持保证 |

这些决定已按本次会话授权进入开发；开发授权不等于发布验收通过。身份撤销当前以完整证书指纹为对象；共用同一证书的设备属于同一身份，不能伪装为可分别撤销。

## 已知原型简化

原型使用示例设备和同步内存事件，不模拟网络栈、异步IPC、真实文件权限或系统授权。指纹显示与图案仅是示例摘要；连接证据由评审事件产生。配置导出预览是节选；日志独立窗口在同页浮层示意；不执行真实本机命令。平台和角色切换器直接选择评审场景，产品角色切换需要事务确认。应用失败示例保留旧版本，真实运行是否恢复要由核心回执报告。

首次手动地址校验和按键／名称校验为示意；产品必须复用真实解析器。暂停的实际传输／输入边界、拓扑同步、逐设备断连与跨输入证据需CAP核验。320宽回退用于评审，不是桌面最小窗口承诺。原型重载会恢复示例，不保存用户设计选择；需要团队留痕请记录本表和缺陷编号。

## 本次实现决定（2026-10-20）

- 沿用 C++ / Qt Widgets 和既有高级配置，HTML 仅用于评审；不改变网络协议格式。
- 稳定 ID／显示名作为本地元数据保存，原路由标识保留；接收端没有完整拓扑同步时只显示实际来源。
- 输入验证采用明确标注的人工确认，不读取测试文字，不把连接当输入成功。
- 核心与服务增加本地 IPC 回执、暂停与按证书身份撤销；停止以实际进程结果为准。
- 来源切换采用用户确认的“短暂中断→尝试候选→失败恢复旧快照”策略；恢复失败显示未确认并请求停止。核对指纹期间暂停计时。
- 先完成 macOS 构建与隔离自动化验证；Windows／Linux、真实双机输入、读屏与系统权限进入实机发布验收。

实际开发、测试环境、功能边界与证据见 [开发与验证记录](测试/产品实现与验证记录.md)。v0.9 原型中保留旧来源不断线的模拟行为属于历史方案，本条决定优先。
