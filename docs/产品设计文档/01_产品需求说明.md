# 01 产品需求说明

版本 v1.0 开发基线；授权与实现证据见 [决策记录](10_整体确认清单与决策记录.md)。需求编号 REQ-01 至 REQ-16 用于跨文档追踪。

## 产品与用户

Deskflow 让一套键盘与鼠标在多台电脑之间使用。现有 GUI 以 C++ / Qt Widgets、Qt Designer `.ui` 为主，macOS、Windows、Linux 共享主要 GUI 与配置逻辑，系统权限、输入后端、窗口和服务采用平台适配。此次设计继续依托既有技术栈；HTML 是评审原型，没有批准切换 Web、Electron 或分别重写原生应用。

面向三类使用者：第一次连接两台电脑的普通用户；每天在混合系统之间切换的多设备用户；依赖复杂排列、映射、配置文件与诊断的高级用户。设计要同时降低首次使用成本，并保留高级配置的表达能力。

## 目标与成功判断

- 用户能直接回答“谁提供键鼠、现在连接了谁、为什么不能控制、下一步做什么”。
- 完成双方身份核对后再连接；连接后单独验证实际输入，避免伪完成。
- 日常以设备和排列为中心，技术设置按意图归类，原有配置可迁移且不丢失。
- 设置失败、系统授权失败和服务停止失败均有恢复入口，不误报完成。

首次连接完成率、从首次启动到首次实际输入的耗时、失败阶段分布、配置迁移成功率和重复通知次数可用于发布后评估。本轮没有基线实测，不编造提升比例。不默认增加遥测；收集任何诊断须明确范围与用户操作。

## 范围与不包含事项

本次交付是桌面 UI 设计规格。包含设备、设置、诊断、帮助、首次设置和系统入口。保留已有服务、协议、证书与文件兼容；不新增云账号、远程桌面视频、互联网中继、移动客户端或自动安装系统服务的承诺。不改变底层输入事件路由或协议格式。实际操作系统授权、跨屏输入检测、逐设备断连、暂停语义和事务应用需要单独接入。

## 术语

| 面向用户 | 工程含义 |
|---|---|
| 这台电脑提供键鼠 / 键鼠来源 | server / source |
| 这台电脑接收输入 | client / receiver |
| 已发现 | 发现服务广告，尚未核对身份或建立会话 |
| 身份已核对 | 本地信任了特定完整指纹，不保证对方同意 |
| 已连接 | 引擎报告安全会话已建立 |
| 输入已验证 | 已完成本次要求的跨屏输入检查，有实际证据或明确人工确认策略 |
| 已保存，待应用 | 持久配置已更新，生效版本尚未替换 |
| 已应用，等待连接 | 运行配置已接受，尚无连接成功事件 |
| 暂停共享 | 用户暂时中止输入共享；实际底层语义需核验 |

显示名称与连接标识分离是拟议数据模型。当前代码按名称存储和引用，迁移时须保留旧引用并建立稳定映射。
