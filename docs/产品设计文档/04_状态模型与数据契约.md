# 04 状态模型与数据契约

版本 v1.0 开发基线；授权与实现证据见 [决策记录](10_整体确认清单与决策记录.md)。以下是拟议的应用层契约，不是已有引擎 API 或网络协议。开发应映射现有 C++ 类型并补齐不能观测的事件，不照搬原型对象到持久配置。

## 状态维度与所有者

| 维度 | 值与关键字段 | 所有者 / 约束 |
|---|---|---|
| 身份与设备 | stableId、displayName、connectionIdentifier、aliases、os | 设备仓库；稳定 ID 拟议，现有名称引用需迁移 |
| 本机角色 | source / receiver；activeRole / candidateRole | 会话协调器；导航不改角色，应用成功才切换运行角色 |
| 能力 | supported / unsupported / unknown、available、reason | 平台适配器；平台名不足以代表实际支持 |
| 进程 | stopped / starting / running / stopping / failed / unknown | 真实进程／服务结果；running 不代表 connected |
| 用户意图 | sharingEnabled、paused、resumePolicy | 用户设置；睡眠唤醒保留暂停意图 |
| 对端信任 | unknown / trusted / changed / revoked；摘要与记录 | 信任仓库；与 transport 独立 |
| 本机身份确认 | identityRevision、peerAcknowledgedRevision | 本机身份改变后远端需重验；不删除远端独立信任 |
| 每设备会话 | offline / discovering / verifying / connecting / connected / failed | 引擎事件；附 reason、lastChanged、attemptId |
| 输入验证 | unverified / checking / verified / failed、evidence、checkedAt | 验证服务；可记录曾验证，当前可用性仍看会话／权限 |
| 草稿 | pageId、dirtyFields、baseSavedRevision、values | 编辑会话；取消不写入 |
| 持久配置 | savedRevision、groups、persistResult | 配置仓库；写入成功才改 revision |
| 生效配置 | activeRevision、snapshot、applyResult、runningWithRevision | 核心协调器；仅应用成功后更新 |
| 窗口与反馈 | visible / hidden / quitting；issues、notificationPermission | UI 协调器；不会反向伪造引擎状态 |

设备首页、菜单栏、标题、诊断由同一应用状态派生，不在每页维护自己的 connected 布尔值。保存配置不要覆盖事件来源状态；迟到事件通过 attemptId、revision 和设备身份检查。

## 关键不变量

1. discovered ≠ trusted ≠ connected ≠ inputVerified；四者不能由一次按钮点击连锁置为成功。
2. savedRevision 可以大于 activeRevision；文件模式取 activeSnapshot.fileMode。只保存外部文件模式不提前锁画布。
3. 变更角色／替换来源是事务：运行旧快照先保留；允许短暂停止旧会话再启动 candidate；失败／取消后用旧快照尝试恢复，实际连接和就绪均确认后才报告恢复成功。
4. changed 或 revoked 的摘要不能自动连接；重新信任不会自动设置 connected。
5. 本机更换身份后所有远端确认旧本机身份的记录失效，本地对远端的信任仍独立存在。
6. stop、pause、hide、quit、serviceDetach 是不同命令；服务停止结果未知不能显示已停止。
7. 对端离线不删除位置；移除配置不等于撤销信任；所有引用更新必须一致提交。
8. 校验失败、持久化失败、应用失败属于不同阶段，错误保留可恢复信息；不依赖“重试次数”降低安全要求。

## 拟议命令与结果契约

所有命令含 commandId、deviceId（按需）、expectedRevision、origin。结果含 success / failure / canceled / unknown、errorCode、可读 reason、recovery、affectedDevices。以下命名是语义标签，非锁定函数签名。

| 命令 | 前置条件 | 成功事件与界面结果 | 失败策略 |
|---|---|---|---|
| BeginDiscovery | 接收端且能力允许 | CandidatesUpdated，仅填发现列表 | 保留手动入口，不改信任 |
| VerifyPeerIdentity | 实际摘要与用户核对记录一致 | TrustStored，等待必要对端确认 | 摘要变化阻断；拒绝不覆盖旧记录 |
| ConnectCandidate | 本地和必要远端确认就绪、权限可用 | SessionConnected，才标记连接 | 结束候选尝试并恢复旧来源；恢复未确认则明确报告并请求停止 |
| VerifyInput | 有连接、权限且目标明确 | InputVerificationCompleted，带证据类型 | 可跳过，保持未验证 |
| SaveDraft | 格式／引用／可写验证通过 | ConfigPersisted(savedRevision) | 不变更保存与生效版本，保留草稿 |
| ApplySaved | 已保存快照可用、说明影响 | ConfigApplied(revision)，独立等待重连 | 记录旧配置是否仍运行，恢复或停机需明确 |
| RevokePeer | 对象身份明确 | TrustRevoked + SessionDisconnected | 若断连未确认，显示待确认并阻止再连 |
| ActivateLocalIdentity | 新身份校验、备份／安全替换准备 | IdentityActivated，停止并要求远端重验 | 保留旧文件及旧 active 身份 |
| PauseSharing / ResumeSharing | 能力可用 | 意图已记录；真实运行结果另回报 | 不隐式调用未知的断连／锁定动作 |
| StopAndQuit | 窗口可返回、有服务控制能力 | CoreStopped，再关闭界面 | 留在界面说明无法确认停止 |
| DetachUi | Windows 已运行服务且用户明确选择 | 界面退出，服务共享继续 | 无法确认服务时不误标仍运行 |
| ResetPreferences / ClearProfile | 路径和范围确认、导出选择 | 明确各组结果；清除后设置助手 | 部分失败逐项报告，不能伪称全清 |

## 配置事务

读当前生效 A → 形成草稿 D → 原有解析器和引用校验 → 写临时／持久保存 S → 用户确认影响 → 对特定 revision 的不可变快照执行应用 → 成功后 active=S。应用期间新的保存产生 S+1；旧成功结果只提交其对应 revision，不能清掉新待应用项。重复回调幂等；取消不会接收已废弃 attempt 的完成事件。

如果现有核心必须先停后启动，应用失败可能导致共享停止，不能承诺运行层无损回滚。界面必须分别报告“配置未替换”“已恢复旧共享”或“共享已停止，需重试”。产品应尽量在停止前完成静态验证，并保留可恢复旧快照。原型保留版本用来说明此边界，未模拟真实进程回滚。

证书路径变更要比较实际公钥指纹而非路径字符串；同文件路径内容也可能改变。维护服务设置、身份激活与普通输入参数的应用影响不同，合并应用前应计算影响集。

## 反馈派生与去重

问题含 key=(code,deviceId,identityRevision,attemptId或episode)、severity、firstSeen、lastSeen、resolvedAt、target、action。重连循环内同一故障 episode 不重复通知；恢复后再次掉线可产生新 episode。前台持久横幅，后台按权限单次重要通知，托盘问题标记保持到真实恢复／已处理。关闭通知不会清除根问题。

汇总优先级：正在退出／停止确认 → 阻断性身份或权限问题 → 暂停 → 正在应用／连接 → 已连接数量 → 等待连接／已停止。每设备行继续显示细分状态，避免总标题掩盖部分异常。

## 数据与隐私边界

原型 `getState()` 仅用于本地测试；没有真实 IPC。生产应最小暴露状态，不把私钥、凭据、剪贴板正文或自动化命令正文放进状态日志／遥测。设备记录、信任、UI 偏好、运行快照和诊断缓存分仓；报告只导出白名单字段并允许预览脱敏。示例见 [状态示例](附录/状态示例.json)。
