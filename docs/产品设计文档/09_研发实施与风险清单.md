# 09 研发实施与风险清单

版本 v1.0 开发基线。用户已授权产品开发；本文件保留实施层次与风险合同，实际进展和证据见 [开发与验证记录](测试/产品实现与验证记录.md)。

## 建议实现分层

沿用 C++ / Qt Widgets；在现有 MainWindow、Settings、CoreProcess、配置模型和平台实现之间补应用状态协调层。页面只渲染状态、提交意图，不直接把按钮点击当成功。

| 模块 | 职责 | 与现有代码关系 |
|---|---|---|
| 应用状态仓库／协调器 | 设备、角色、会话、配置版本、问题派生 | 聚合核心／系统信号；全部页面和托盘共用 |
| 配置编辑会话 | 页面／弹窗草稿、验证、持久化、应用快照 | 复用 Settings 和真实配置模型；补事务边界 |
| 设备与引用仓库 | 标识、别名、映射、角落、规则引用一致性 | 接入 Computer / ServerConfig，迁移旧名称键 |
| 信任与身份适配 | 真实摘要、变更、撤销、远端确认 | 接入现有指纹／TLS逻辑；不得在GUI复制加密实现 |
| 平台能力适配 | 权限、托盘、服务、全局快捷键、通知、生命周期 | 分平台检测，不靠页面散布平台判断 |
| 验证与诊断 | 阶段结果、未知状态、输入证据、报告脱敏 | 接入日志／核心事件，诊断不自动降低安全 |
| Qt 视图与组件 | 导航、表单、完整画布、状态、弹窗 | 提炼共享组件；遵循原生焦点／可访问接口 |

HTML原型不是嵌入产品的目标UI框架。是否更换渲染技术应另行论证并获得明确决定，本次没有此决策。

## 技术前置与风险账本

| 编号 | 未验证点／风险 | 必需的验证成果 | 不可擅自采用的降级 |
|---|---|---|---|
| CAP-01 | 暂停是否可单独阻止键鼠／剪贴板、保持哪些会话 | 明确真实语义及事件，暂停／恢复／睡眠实测 | 用停止或锁光标冒充暂停 |
| CAP-02 | 按设备撤销信任并立即终止指定会话 | 断连API、回执及阻止重连证据 | 撤销列表但连接继续却显示已断 |
| CAP-03 | 设备友好名称、稳定ID、指纹关联及迁移 | 旧名引用迁移／碰撞方案和回滚测试 | mDNS名称当身份，静默改标识 |
| CAP-04 | 接收端完整拓扑同步 | 协议是否有数据、更新权限和版本设计 | 没数据时猜测绘制完整图 |
| CAP-05 | 跨屏输入验证事件 | 可观测事件与准确性／隐私，或经确认的人工证据方案 | 点击下一步直接已验证 |
| CAP-06 | 配置保存／应用分离与运行回滚 | snapshot/revision合同、失败时运行状态和迟到事件测试 | 保存即应用或应用失败假称仍运行 |
| CAP-07 | Portal、通知、全局快捷键、权限恢复 | 实际平台能力表和拒绝／撤销路径 | 声称所有Wayland桌面支持 |
| CAP-08 | 活动配置目录、外部文件、服务相关路径 | 实际文件清单与清理预览、部分失败处理 | 按猜测路径递归删除 |
| CAP-09 | 真实配置解析／完整序列化 | 旧样本全字段语义往返、未知字段策略 | 用原型链路节选导出 |
| CAP-10 | 服务停止确认与明确退出 | Desktop／Service 回执、超时、关机处理 | GUI结束视为共享停止 |
| CAP-11 | 普通偏好立即生效、系统注册状态 | 按字段分类，区分保存与系统接受 | 切一个开关全部显示已启用 |
| CAP-12 | 结构化诊断与报告脱敏 | 白名单、地址／名称／敏感正文检测、预览导出 | 原始日志打包上传 |

这些是待实现合同，不是文档漏项。研发负责人需记录结论、证据和影响页面；无法满足时给具体替代方案回到整体设计确认。除非确有核心要求，不预先承诺协议重构或服务安装行为。

## 建议实施批次

| 批次 | 可评审产出 | 依赖与退出条件 |
|---|---|---|
| A 技术核验与迁移基线 | CAP结论、旧配置样本、平台能力、状态合同 | 产品设计整体确认；无数据破坏风险 |
| B 共用骨架与状态 | 导航、全局状态、草稿／保存／应用边界、托盘共用模型 | CAP-06、10、11，模型／事件测试通过 |
| C 首次连接与信任 | 来源等待、接收发现／手动、双向确认、失败恢复 | CAP-02、03、05、07，真实两机闭环 |
| D 设备与全部高级能力 | 完整画布、设备选项、动作、接收端、外部配置 | CAP-09，106迁移语义验证 |
| E 维护与系统行为 | 服务、证书、清理、暂停、通知、生命周期 | CAP-01、08、10，实机失败注入 |
| F 诊断、无障碍与发布 | 日志／报告、视觉、文案、迁移／平台验收 | CAP-12，P0证据和整体复核 |

每批可以做草图与已授权设计材料，但产品代码开始前需确认本轮总体方案。实现中新增能力与旧行为冲突要更新决策记录，不能临时删高级能力赶进度。

## 团队交接责任

产品负责人确认行为／文案与发布范围；设计负责人确认所有页面及主题／状态；工程负责人确认CAP、架构、旧格式和平台差异；测试负责人落实AT矩阵、实机证据与迁移；安全相关身份／报告由负责该模块的工程师复核。此处为建议责任角色，未编造姓名或已签署结论。
