## 建议整体确认顺序

1. 从“首次设置开始”，分别走提供键鼠、接收输入两条路径；完整核对身份、等待对方确认、建立连接、排列和输入验证。
2. 恢复六台电脑示例，添加一台电脑；再以接收端更换来源并模拟失败，确认原连接保留。
3. 调整完整排列，编辑设备别名／映射／角落，再添加多动作快捷键；检查保存、待应用、应用失败、应用成功、重新连接的区别。
4. 撤销信任、更换身份、模拟掉线与权限缺失，在设备、诊断和菜单栏面板观察一致状态。
5. 切换四种平台；核对 Windows 服务退出、无托盘入口、通知未允许、Wayland 授权限制。
6. 依照 [整体确认表](10_整体确认清单与决策记录.md) 记录接受或具体修改点，再形成 v1.0 冻结版。

## 文件优先级与边界

经确认的需求与状态规范决定产品行为；页面规范决定交互，视觉规范决定呈现。贯通原型供流程评审，原型内部实现不作为产品架构、加密、解析或序列化实现。旧轮草图只作为历史参考；与本目录冲突时按本版说明评审，不并行实施旧简化方案。

106 条是既有 `.ui` 交互控件库存，不代表全部引擎能力数量，也不代表实现已完成。文档另列动态菜单、系统权限、服务和配置完整性。示例地址使用文档网段；指纹与日志均为虚构。原型不会读写实际配置、联网、监听输入或执行命令。
