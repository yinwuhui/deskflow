## 1. 背景与目标

核心需求：在现有连接方式、首页及服务端/客户端选择保持不变的基础上，为已经建立连接的设备增加“键鼠共享 / 扩展屏幕”用途切换。入口仅位于“设备列表”和“屏幕排列”的设备属性区。两种用途对同一设备关系互斥，设备身份和基础连接保留。

| 用户选择 | 对方屏幕显示什么 | 本机鼠标操作什么 | 本机键盘归属 |
| --- | --- | --- | --- |
| 键鼠共享 | 对方电脑原有的桌面 | 对方自己的应用；按已配置屏幕边缘进入/退出 | 随鼠标控制焦点切换，操作当前所在电脑的应用 |
| 扩展屏幕 | 本机新增的桌面区域 | 本机的应用，可以将本机窗口拖到该区域 | 操作本机应用，不向接收端系统回传 |

键鼠共享同时提供本机鼠标和键盘，两者按同一跨屏控制焦点工作。本版撤销 v1.1 的仅鼠标默认值与可选键盘方案，不提供独立的“同时共享键盘”开关。扩展屏必须加入发送端当前交互桌面的显示拓扑。镜像主屏、共享单个窗口、另建远程登录桌面不算完成。

目标流程：“按原方式建立连接 → 在设备列表或屏幕排列中选择已连接设备 → 切换用途”。软件负责新增显示权限、对方确认、停止旧用途、启用新用途与失败恢复，不要求重新输入服务端或改变连接角色。

本版为增量特性：不重构首页、不替换连接方式、不新增首页模式选择，不改变局域网/蓝牙原有连接操作。

本版撤回 v1.1/v1.2 中“目标电脑 + 使用模式取代首页角色与连接区”的要求。此前原型只可作为颜色与基础组件参考，页面入口和连接流程必须按 v1.3 更新。

## 2. 当前能力与证据边界

本节依据仓库现有代码和实验记录，不将设计目标视为实现结果。

| 能力 | 当前证据 | 产品化缺口 |
| --- | --- | --- |
| 公共显示协议和状态基础 | `src/lib/display/Protocol.*`、`Session.*` | 尚需接入产品协调服务与 GUI |
| Mac / GNOME 虚拟屏、采集、编码 | 阶段 A/B 实机实验 | 平台兼容矩阵、稳定性与打包 |
| Mac ↔ Linux 加密视频传输 | 阶段 B TLS 双向认证与解码实验 | 产品发现、信任授权、原生媒体链路 |
| 可见画面 | 已有实验接收窗口；阶段 B 未完成可见画面验收 | 首帧呈现确认、实机画质验收 |
| 键鼠共享 | 已有跨电脑键鼠链路 | 复用并验证鼠标/键盘焦点一致、按键释放、平台快捷键和模式互斥 |
| 接收端键鼠输入 | 有租约/释放基础；实验 `inputEnabled=false` | 输入注入、焦点、权限与映射尚未贯通 |
| 双模式切换 | 现有显示状态基础不等于产品切换协调器 | 需统一设备会话、互斥、预检、切换代次与失败恢复 |
| 自动重连、自适应码率 | 当前实验未提供 | 后续实现，首版 UI 不承诺 |
| Windows | 尚无实机验收 | 驱动、发送/接收后端、签名和验证 |
| 产品开关 | `BUILD_VIRTUAL_DISPLAY` 默认关闭 | 需要独立产品准入与能力控制 |

现有“传输成功”“收到数据”“解码完成”“提交显示层”均不能单独替代用户实际看到画面的验收。不得用当前无效采集时间戳计算或显示端到端延迟。

## 3. 角色与术语

| 术语 | 定义 | 面向用户的用语 |
| --- | --- | --- |
| 用途请求端 | 在设备列表/排列中对已连接设备请求切换用途的本机，不代表切换输入角色 | 本机 |
| 目标端 | 在当前设备关系中被选中的另一台电脑 | 工作电脑等真实设备名称 |
| 使用模式 | 同一设备关系的互斥用途，input / extended | 键鼠共享 / 扩展屏幕 |
| 显示发送端 Host | 扩展模式中创建虚拟屏、运行应用、发送画面的电脑 | 本机 |
| 显示接收端 Receiver | 扩展模式中接收副屏画面的目标电脑 | 正在提供扩展屏的电脑 |
| 键鼠来源端 | 键鼠模式中同时提供鼠标和键盘的电脑 | 键鼠来源电脑 |
| 键鼠受控端 | 键鼠模式中接受输入、运行自身应用的电脑 | 被操作的电脑 |
| 已信任设备 | 经身份验证并获用户信任的设备 | 已信任 |
| 显示授权 | 本次使用目标屏幕的明确同意 | 允许本次使用 |

后端仍需分别记录输入来源/受控角色和显示发送/接收角色，不能只复用现有 server/client 布尔值。首页继续以“共享本机键鼠 / 使用其他电脑的键鼠”表达输入角色；新增用途只在设备列表和屏幕排列中表达，不替换首页原有操作。

同一设备关系只能有一种有效模式：未使用、键鼠共享或扩展屏幕。可以保留已认证的基础连接，但不得同时启用操作对方桌面的路由与本机扩展屏路由。其他设备各自的模式独立；首版每台电脑仍最多参与一个扩展显示会话，显示发送与接收互斥。

用途切换不改变现有输入服务端/客户端角色、服务端地址或证书身份。显示发送/接收方向独立协商：本机请求将对方屏幕作为本机扩展屏时，本机是显示发送端；恢复键鼠用途时恢复原有输入方向。本机原为输入客户端时，继续使用原服务端的键鼠，不能静默反转成共享本机键鼠。对应能力不支持时提前禁用并说明原因。

## 4. 范围与优先级

### 4.1 P0：首个产品版本

1. 复用现有服务端/客户端、地址输入、设备发现、局域网/蓝牙及信任流程；只对已连接设备新增用途能力检查。
2. 接收端每次会话明确同意，发送端按需处理系统采集权限。
3. 一个虚拟副屏、一个接收窗口、一个接收物理屏。
4. 窗口显示、全屏、切换目标物理屏、结束会话。
5. 屏幕排列中区分本机屏幕、远端电脑屏幕、虚拟扩展屏。
6. 固定区位和自由排布沿用已有交互，实际布局以系统确认结果为准。
7. 在设备列表及屏幕排列设备属性区提供同步的“键鼠共享 / 扩展屏幕”切换；首页布局和原有角色切换保持。
8. 手动重试、双端结束、超时回收、崩溃清理、重启残留检查。
9. 仅发送端本机键鼠操作其扩展桌面；接收窗口默认不回传输入。
10. 键鼠模式同时共享本机鼠标和键盘，不拆分键盘开关；实现同设备双模式互斥切换与失败恢复，见第 10 节。

首版建议固定初始档位为 1920×1080、SDR、目标 30fps，H.264。参数代表待验收目标，实际帧率不达标不得按“30fps 已支持”发布。接收窗口缩放不自动改变虚拟屏分辨率。

### 4.2 P1：稳定性增强

接收端输入回传与控制权、自动重连、会话内分辨率调整、适配物理屏的分辨率与缩放、画质/流畅档位、自适应码率、可靠的实际帧率与延迟诊断。

P1 不因协议已有同名消息就被视为已完成；按完整链路验收后开放 UI。

### 4.3 本版不包含

互联网中继、蓝牙视频、音频、镜像模式、文件拖放、多接收端、多虚拟屏、HDR、4K/HiDPI、触摸与笔输入、登录界面/安全桌面、无人值守解锁。

键鼠模式可以使用现有已支持的蓝牙输入通道；扩展模式必须另外验证可达且受认证的网络通道。蓝牙连接不能用来推断视频能力；切换预检不通过时保持原键鼠模式。

## 5. 信息架构与视觉规范

### 5.1 入口分工

| 页面 | 责任 | 主要入口/操作 |
| --- | --- | --- |
| 首页 | 保持现有输入角色与连接流程 | 共享本机键鼠 / 使用其他电脑的键鼠、局域网/蓝牙、服务端地址/设备、连接/共享按钮 |
| 屏幕排列 | 原有排列与设备属性的增量扩展 | 选中远端电脑，在属性区切换用途、配置位置、查看状态 |
| 设备列表 | 原有设备管理及设备级用途切换 | 已连接设备提供键鼠共享 / 扩展屏幕，未连接设备沿用原连接入口 |
| 高级设置 | 模式偏好与诊断 | 扩展屏接收请求开关、模式说明、诊断入口；不增加键盘共享开关 |
| 接收画面窗口 | 显示副屏内容 | 全屏、退出全屏、显示详情、结束扩展 |

所有入口调用同一个会话协调服务，共享状态与防重复逻辑，不各自建立连接。

### 5.2 共同布局

- 主窗口保持既有 1000×700 Qt 逻辑像素及小工作区适配策略；不增加主窗口缩放能力。
- 接收画面是独立媒体窗口，可调整大小和全屏，不受主窗口固定尺寸限制。
- Windows/Linux 共用产品布局；macOS 保留系统窗口行为和原生字体。
- 首页顶部卡片仍只展示本机身份、网络、蓝牙信息，不重复列入扩展屏状态卡。
- 新控件嵌入现有设备行/卡片或排列属性区，沿用页面边界、间距和蓝色选中样式；切换状态不引起卡片或按钮跳动。
- 不依赖颜色单独表示用途/状态；图标同时配文字，错误提供具体恢复动作。
- 中文、英文、长设备名和高 DPI 均须可用；完整设备名可通过可访问名称与提示查看。

## 6. 首页与连接方式：保持现状

### 6.1 冻结的首页结构

本特性不重新设计首页。以下现有功能及其位置、语义、配置入口继续保留：

- 顶部本机信息卡片：设备名、局域网 IP、蓝牙信息。
- “共享本机键鼠 / 使用其他电脑的键鼠”角色切换。
- 共享端原有局域网/蓝牙开启方式与“开始共享/停止共享”。
- 客户端原有局域网/蓝牙选择、服务端地址输入或附近设备选择、“连接/断开”按钮。
- 原有备用连接选项、查找/刷新设备、屏幕排列入口和底部状态。

不添加替代现有角色选择的“键鼠共享 / 扩展屏幕”首页切换，不增加目标电脑选择卡，不因本特性加入常驻“当前连接”新模块，也不重新分配首页留白。首页至多在既有状态/提示位置反映必要的共享或错误状态，不增加新的连接步骤。

### 6.2 先连接，再选用途

服务端照常开启共享，客户端照常选择或输入服务端并连接。连接及身份验证成功后，设备列表与排列页获得已连接设备及其能力。

用途切换以该已建立关系为基础，不断开后要求重连，不改写服务端地址，不切换首页角色，不修改用户原有自动备用输入连接设置。

未连接设备的用途切换禁用，提示“请先建立连接”。用户使用现有设备操作或返回首页原连接区；不新增独立的扩展屏配对、设备选择或地址输入向导。

### 6.3 原连接操作与用途的边界

- 首页“断开”或“停止共享”仍按现有范围结束基础连接；依赖它的扩展会话同时结束并清理。
- 设备中“结束扩展”只结束显示用途，保留可用基础连接；不自动控制对方原桌面。用户选择键鼠用途后才恢复其输入路由。
- 仅蓝牙建立的关系可以继续用于键鼠共享；扩展屏需额外的认证网络视频通道。缺少 LAN 时在设备用途操作处解释原因，不改变首页蓝牙连接方法。
- 首页输入角色切换沿用现有行为；若会影响进行中的扩展，明确提示并按原连接生命周期清理，不静默把显示用途转成另一种输入方向。
- 显示接收端的授权请求采用应用内确认提示，不借此重构首页为新的连接/模式面板。

## 7. 屏幕排列页需求

### 7.1 画布与属性

保留现有页内导航、固定区位/自由排布开关、画布和已有添加电脑行为，不新增扩展屏连接向导。选中已经连接的远端电脑后，在设备属性区增加“使用模式”。显示对象明确分类：

| 对象 | 画布标签 | 含义 |
| --- | --- | --- |
| 本机物理屏 | 本机屏幕 · 1 | 本机已有物理输出 |
| 键鼠模式的目标电脑 | 工作电脑 · 键鼠共享 | 移入后操作对方原来的桌面与应用 |
| 本机会话虚拟屏 | 工作电脑 · 扩展屏 | 移入后继续操作本机应用 |

选中对象时，在固定属性区域显示设备名、用途、状态、位置与可用操作；不自动弹出原始配置窗口。画布缩放只影响预览，不改变真实显示分辨率。

“使用模式”直接提供“键鼠共享 / 扩展屏幕”两个互斥选项，与设备列表对应设备实时同步，由同一个协调服务驱动。选择本机物理屏时不显示远端用途开关；选择未连接设备时禁用并说明需先连接。同一远端设备不能同时出现两个可交互用途节点。

### 7.2 设备连接状态与能力

设备来自现有连接管理和发现结果。刷新设备不自动申请显示权限，不逐台探测或配对附近蓝牙外设。

| 状态 | 用途控件 |
| --- | --- |
| 已连接且支持显示 | 允许切换，附当前有效用途 |
| 已连接但对端版本不支持显示 | 键鼠用途可用，扩展选项禁用并说明需更新 |
| 已连接但缺少 LAN 视频路径 | 原键鼠用途保持，扩展操作预检失败并提示网络条件 |
| 未连接/离线 | 两种用途不可启用，提供原有连接操作/前往首页 |
| 正在切换/清理未完成 | 禁止重复切换，提供取消或重试清理 |
| 已有其他扩展会话 | 显示忙碌，不抢占其他设备 |

能力检查、使用授权与基础连接分开；输入连接成功不自动获得显示许可。

### 7.3 排列规则

- 新屏首次默认放在本机主屏右侧，不覆盖现有显示器；若系统无法采用该位置，展示真实结果并提示原因。
- 固定区位模式按既有吸附规则排列；自由模式允许上下错位，禁止重叠，至少有一段可跨越的相邻边界。
- 产品以统一逻辑坐标描述跨 DPI 布局，平台适配层负责转换，不直接混用视频像素和 UI 逻辑像素。
- 扩展屏位置变更必须调用显示后端，不能只写现有键鼠屏幕配置；普通电脑位置仍更新键鼠配置。
- 拖动先预览、释放后提交；保存期间禁止重复提交同一对象。后端确认成功后显示已保存；失败恢复最近确认布局。
- 无法提供布局能力的平台允许使用系统显示设置；相关控件禁用并给出入口，不展示无效拖动。
- 首版分辨率显示“1920×1080”；接收窗口提供“适应窗口/原始大小”。未认证的分辨率、缩放、刷新率不提供可选项。

### 7.4 设备列表中的增量控件

保留原设备列表的分类、设备名称、系统信息、连接状态与原有操作。对已连接电脑，在其卡片/行的详情区域新增一行：

> 使用模式　[键鼠共享] [扩展屏幕]

下方用一条短状态说明当前用途；扩展使用中提供“屏幕排列”“结束扩展”，接收端可提供“显示画面”。未连接设备只解释需先连接，不另设模式连接按钮。

两个页面的用途控件使用相同标签、选中颜色、状态与错误文案；一个页面切换后，另一页面自动反映真实结果。局部状态区预留高度，长名称截断带完整提示，不能改变整页布局。

### 7.5 切换过程与状态表达

点击另一用途即请求切换，只影响该设备。等待对方允许时仍标明旧用途有效；进入停旧/清理阶段显示阶段信息；目标真正就绪后再标记选中用途已生效。切换中禁用重复提交，允许取消，结果按第 10 节恢复规则展示。

不新增一次“先在首页选模式”的步骤。设备列表和排列页只表达同一份设备用途状态，不能各自持久化互相矛盾的值。

## 8. 端到端用户流程

### 8.1 首次建立

1. 用户按原流程建立设备连接，在“设备列表”或“屏幕排列”中选中该已连接电脑，再选择“扩展屏幕”。
2. 在原设备身份和基础连接上预检版本、显示发送/接收能力、网络视频路径、占用及组件；不改变输入服务端/客户端角色。
3. 复用已有设备身份信任；若身份变化则按原安全流程重新核对。本次屏幕使用授权仍独立取得。
4. 接收端在应用内显示请求；主窗口后台时使用系统通知提示，通知不代替应用内确认。
5. 接收端选择“允许本次使用”或“拒绝”。默认不永久允许，30 秒未处理自动过期；发送端可随时取消。
6. 发送端处理系统采集/虚拟屏权限；等待系统操作时暂停应用超时，并提供取消，不冒充权限已授予。
7. 确认同意与权限后创建虚拟屏、建立受认证通道、准备解码器并打开接收窗口。
8. 接收端确认第一帧已经进入实际呈现路径后，产品进入“扩展屏使用中”。
9. 发送端显示排列入口；接收端默认以适应画面的窗口显示，由接收端用户选择全屏。

准备失败或任一步取消，回收本次创建的资源，不保留半初始化副屏。对端尚未接受时不创建虚拟屏；若由键鼠模式切换而来，按第 10 节保留或恢复旧模式，不能静默并行。

### 8.2 接收请求

应用内文案示例：

> “我的 Mac mini”希望使用这台电脑的屏幕。允许后，这台电脑将显示对方的扩展桌面。
>
> [拒绝] [允许本次使用]

请求显示已验证的身份摘要/信任状态，可展开核对指纹。同名设备不能冒用已有授权。请求过期或发送端取消时，确认按钮立即失效；晚到的“允许”不得建立新会话。

用户锁屏、系统会话不可用或正在参与另一扩展屏会话时，不自动接受；给发送端返回明确状态。并发请求只允许一个活动请求，其他请求返回忙碌，不堆叠多个授权框。

### 8.3 后续使用

记住设备选择、上次选中模式、两种模式各自的位置配置、目标物理屏和窗口显示偏好。新建关系和已有关系均以整体键鼠共享定义该模式，不新增独立键盘共享偏好；v1.1 文档中提出的仅鼠标偏好和迁移要求废止。不记住有效会话令牌、不自动恢复显示授权、不在启动后自动创建副屏。再次进入扩展模式仍需接收端本次允许。

### 8.4 正常结束

两端均可“结束扩展”，不需另一端二次批准。发送端显示“正在结束扩展…”；停止画面、释放本会话资源、确认虚拟屏从系统拓扑消失后再显示结束完成。

主动结束前提示副屏上的窗口将按系统行为回到可用屏幕，不保证恢复到某一精确坐标。通知仅在需要时出现，不要求每次结束弹确认窗。结束后保留目标设备与扩展模式选择，状态为未使用；不得自动开始操作对方原桌面的键鼠模式。只有用户明确切换到键鼠共享时才可启用该用途。

## 9. 接收画面窗口

- 独立窗口标题为“我的 Mac mini — 扩展屏”；清晰标明发送来源。
- 顶部工具栏包含来源、连接状态、全屏/退出全屏、显示详情、结束扩展。
- 首版不提供可用的“控制对方”按钮；详情说明“当前仅显示画面，本机键鼠不回传”。
- 默认保留完整画面比例；适应窗口时等比例缩放并留边，不拉伸、不裁掉桌面边缘。
- 全屏仅占用接收端选定的一块物理屏，不接管所有显示器。
- 全屏工具条可自动隐藏；鼠标触顶可唤出，Esc 退出全屏，不直接结束会话。
- 接收窗口未启用输入回传时不锁定光标、不隐藏系统退出入口；本机键鼠仍属于接收端本机。
- 最小化接收窗口不等于结束；状态变为“接收窗口已最小化”，仍可从首页“显示画面”恢复。是否降帧由后端能力决定，未实现不声称节能。
- 点击接收窗口关闭按钮等同“结束扩展”，不得仅隐藏窗口并继续占用虚拟屏。
- 主窗口关闭继续遵循既有托盘设置；显示会话期间若无法留在后台，需要明确告知退出将结束扩展。
- 显式退出整个应用时结束会话并清理；清理失败保留可诊断信息，不能伪报成功。

## 10. 互斥模式、键鼠控制与切换规则

### 10.1 键鼠共享作为一个整体

- 同时共享本机鼠标和键盘；鼠标移动、定位、按钮、滚轮以及键盘输入按现有跨平台输入规则传递。此模式不传输桌面画面，不创建虚拟屏。
- 鼠标跨入目标电脑的边缘后，键盘随同一控制焦点操作目标原有桌面；鼠标回到本机后，键盘同步回到本机。不能出现鼠标在目标电脑而键盘始终留在本机的默认行为。
- 普通文本输入、修饰键和常用组合键按既有平台映射处理；系统保留快捷键遵循操作系统限制，不承诺可转发全部安全桌面操作。
- 不提供单独的键盘开启/关闭选项，也不新增用于拆分键盘和鼠标的持久化配置。
- 结束共享、断线、焦点交接或模式切换时，可靠释放已转发的键/鼠标按下状态；未能确认释放时撤销输入控制并由超时机制兜底。
- 不能在按住某键/按钮期间直接将按下状态转交给新桌面。过渡阶段停止注入新输入，先释放旧控制状态，再启用新路由。
- 共享开启后按排列边缘切换控制焦点，默认将焦点保留/带回本机，不因点击模式按钮突然点击或键入对方窗口。
- 首次连接受控端仍走现有可信连接与键鼠控制许可流程。若键盘或鼠标所需权限不完整，保持模式未启用并明确提示权限缺口，不静默降级为仅鼠标。
- 显示授权与键鼠控制许可分别处理；取得其中一项不等于取得另一项。

### 10.2 从键鼠共享切换到扩展屏幕

1. 保留目标设备与原模式配置，创建唯一切换操作代次。
2. 预检双端显示能力、LAN 路径、占用和系统权限，向对方请求本次显示授权。预检/等待期间原键鼠模式可继续；不能先停掉可用模式再提示缺少网络。
3. 所需许可全部就绪后，通知两端正在切换，撤回目标电脑的鼠标/键盘输入所有权，释放所有按下状态，将控制焦点带回本机。
4. 确认旧路由停用后创建虚拟屏、建立视频和呈现路径。屏幕位置使用扩展模式配置；不直接覆盖键鼠模式配置。
5. 首帧呈现后标记扩展模式生效；鼠标进入该屏时继续操作本机应用，禁止旧边缘规则将输入送到对方原桌面。

不新增连接向导，不要求重新选择服务端或切换首页角色；在设备用途切换意图明确时自动暂停该关系原有输入路由，保留其方向和配置以供恢复。需要用户确认的仅是新增权限、对端使用许可或无法自动解决的限制。

### 10.3 从扩展屏幕切换到键鼠共享

1. 保留原设备关系、服务端/客户端角色和输入方向，预检完整键鼠控制能力及权限；键盘和鼠标都可用后才开始停止旧用途。
2. 确认新模式可启用后，结束扩展、关闭接收画面并确认本会话虚拟屏从系统拓扑消失。窗口按系统行为回到可用屏幕。
3. 清理完成后才恢复该关系原有键鼠路由与位置配置；本机是来源端则继续提供键鼠，是受控端则继续接收原服务端键鼠。键盘与鼠标保持同一控制焦点。
4. 两端显示“键鼠共享已开启 / 正在使用来自…的鼠标和键盘”，操作对象变为对方原有桌面。

清理失败则阻止键鼠模式生效，进入 CleanupRequired。不能因 UI 已切到左侧就认为输入路径已经安全切换。

### 10.4 取消、失败与互斥保证

| 场景 | 结果 |
| --- | --- |
| 预检失败、对方拒绝、等待超时或取消，旧模式尚未停止 | 保持原模式；选择器回到实际模式，保留失败原因 |
| 键鼠→扩展：停止旧路由后，扩展准备失败 | 先清理本次虚拟屏；仅在原控制授权和连接仍有效、用户未另行停止时恢复原键鼠模式及其焦点/位置配置 |
| 键鼠→扩展：旧授权失效或资源清理失败 | 保持未使用或 CleanupRequired，不能伪报已恢复；提供重试/清理 |
| 扩展→键鼠：扩展已结束但键鼠共享启用失败 | 两种模式均不启用，显示“扩展已结束，键鼠共享未能开启”；重新扩展需重新取得本次许可，不能偷偷重建副屏 |
| 故障断开或用户点击结束扩展 | 结束当前模式，不自动切成操作对方原桌面的键鼠模式 |
| 切换中再次点击或其他入口开始 | 复用/拒绝同一操作，不创建第二个用途；新意图和晚到事件按代次处理 |
| 切换中用户明确结束全部使用 | 取消切换并清理，不因旧请求失败回调重新激活任何模式 |
| 其他电脑有既存共享 | 保留与当前目标无冲突的用途；无法隔离时在停止旧模式前说明限制并中止切换 |

“只能同时生效一种模式”是 P0 发布条件。若输入后端无法按目标隔离，需补齐协调能力；不能以同设备并行或偷偷停止所有连接替代。

### 10.5 P1 接收端控制

扩展模式下，接收电脑自身的鼠标和键盘默认仍属于其本机。通过接收电脑的键鼠回传操作发送端扩展桌面属于 P1，需单独授权、唯一输入租约、失焦/断线释放和坐标转换。它与本版“发起端提供键鼠操作目标电脑原桌面”的键鼠共享模式方向和语义不同。

## 11. 状态、异常与恢复

显示子会话按现有 `SessionState` 组织；它不足以单独表达键鼠模式与模式切换。新增设备用途协调状态 `Inactive / InputActive / DisplayActive / Switching / CleanupRequired`，并记录目标模式、实际生效模式及阶段。拒绝/过期等结果由协调层保存，成功清理后底层可回到 Idle，GUI 不丢失终止原因。

| 状态 | 可见文案 | 可用动作/退出条件 |
| --- | --- | --- |
| Idle | 当前用途未启用 | 设备仍连接时可在设备列表/排列页选择用途 |
| Connecting | 正在连接电脑 | 取消；失败后重试 |
| Authorizing | 等待对方允许 / 等待系统授权 | 取消、打开对应系统设置 |
| Negotiating | 正在检查显示能力 | 取消；不支持时说明原因 |
| Preparing | 正在准备扩展屏 | 取消；资源完成且真实首帧呈现后进入使用中 |
| Streaming | 扩展屏使用中 | 排列、显示画面、结束 |
| Reconfiguring | 正在应用显示设置 | 等待、结束；失败回滚 |
| Recovering | 连接中断，正在结束扩展 | P0 释放资源；P1 有自动恢复能力后才显示“重连中” |
| Stopping | 正在结束扩展 | 阻止重复开始；清理完成后结束 |
| CleanupRequired | 扩展屏未完全释放 | 重试清理、详情、系统显示设置 |

每次开始、取消、重试和模式切换使用独立操作代次；过期响应、旧帧和旧会话通知不得改变当前 UI。所有按钮依据真实快照更新，重复点击不创建重复屏幕或输入路由。切换失败需同时返回旧模式是否仍有效、是否已恢复、资源清理结果，不能只返回显示子会话 Idle。

| 异常 | 产品行为 |
| --- | --- |
| 找不到设备/网络不可达 | 保留选择结果，提供刷新、修改地址；不误导用户去开启蓝牙视频 |
| 版本过旧/不支持接收或发送 | 明确指出哪一端缺什么能力，提供更新或返回 |
| 对方拒绝/请求超时 | 显示“对方已拒绝/请求已过期”，不自动连续重发 |
| 屏幕采集权限不足 | 区分系统权限与对方许可，提供准确设置入口和重新检查 |
| 目标正忙 | 显示正在使用中，不抢占或结束他人会话 |
| 证书变化/身份验证失败 | 停止会话，要求重新核对身份，不能自动接受 |
| 蓝牙已连但没有网络路径 | 扩展切换预检失败，提示“扩展屏需要局域网连接”，原键鼠共享保持可用 |
| 解码/首帧呈现失败 | 清理虚拟屏，按第 10 节恢复原键鼠模式或保持未使用；不假报扩展已生效 |
| 严重拥塞/网络断开 | 对旧画面覆盖“连接已中断”，停止可交互假象，释放虚拟屏，提供手动重试 |
| 任一端锁屏/睡眠/用户切换 | P0 结束会话并清理；解锁后由用户重新发起 |
| 接收物理屏拔出 | 退出全屏并移到可用屏，提供选择；没有可用输出则结束 |
| 发送/接收进程崩溃 | 由存活端和资源拥有者监督清理；下一次启动检查残留 |
| 创建/布局失败 | 回滚本次更改，不能删除用户其他真实或虚拟显示器 |
| 清理失败 | 保持 CleanupRequired，不允许重建同一会话资源；提供明确恢复入口 |

P0 不把键鼠通道自动切换等同于视频通道切换。视频断开后禁止自动降级为蓝牙传输。

## 12. 权限、信任与设置

- 显示发送只采集本会话创建的虚拟屏；不能静默采集物理主屏。
- 设备身份信任、本次屏幕使用、系统屏幕采集、远程键鼠控制分别解释和处理，不互相推定授权。
- 产品复用现有身份基础时需明确兼容映射，不直接把实验 `--peer-cert` 或 SSH 交换证书流程暴露给用户。
- 高级设置增加“允许其他电脑请求使用这台电脑的屏幕”，建议默认开启请求接收，但每次仍需允许；关闭后拒绝新请求，不自动终止当前会话。
- 关闭请求接收时提示当前会话仍在进行，并提供独立“结束当前扩展”操作；重启后保留该偏好。
- 键鼠模式按整体检查鼠标和键盘控制权限；权限不足时说明原因并阻止启用，不以仅鼠标状态假报整体已就绪。
- P0 不提供“永久自动允许”“自动全屏”“开机自动建立扩展屏”。
- 不在日志写入画面、键入内容、私钥或会话令牌；诊断导出前说明包含系统、设备身份摘要与连接错误。
- macOS 缺少所需能力、Windows 缺少已验证组件、Linux 桌面不支持虚拟输出时，禁用对应发送能力；接收能力独立检查。

## 13. 前后端能力与接口需求

以下为 GUI 所需的协调服务契约建议，属于待实现接口，不代表现有类已全部提供。实现语言和函数名可调整，但语义必须保留。

### 13.1 能力查询

`queryLocalDisplayCapabilities()` / `queryPeerDisplayCapabilities(peerId)` 返回：

- 整体键鼠共享、鼠标/键盘焦点同步、完整输入权限、按目标暂停/恢复路由、释放确认、互斥模式切换等能力；
- 显示发送、接收、排列、全屏、分辨率配置、接收端输入、重连等各自能力；
- 支持的分辨率/刷新率/编码配置，以及能力不可用的可展示原因；
- 系统会话可用性、所需权限、组件安装状态、当前占用情况；
- 兼容协议版本。区分 unknown / checking / supported / unsupported，不能把未查到当作不支持。

### 13.2 操作与事件

| 建议操作 | 语义 |
| --- | --- |
| queryPeerUsageCapabilities(peerId) | 统一查询两种用途、完整键鼠控制及路由隔离能力，包含许可缺口 |
| queryConnectedPeerUsage(peerId) | 复用现有连接管理取得设备关系、输入角色、方向与用途能力，不另建选择/连接流程 |
| startPeerUsage(peerId, mode, options, operationId) | 仅在已连接关系上启用用途；input 恢复原输入角色/方向，extended 建立附加视频会话 |
| switchPeerUsageMode(peerId, targetMode, operationId) | 预检、取得许可、停旧、清理、启新与失败恢复的唯一事务入口 |
| cancelPeerUsageOperation(operationId) | 按切换阶段取消，明确返回原模式是否仍有效 |
| stopPeerUsage(peerId, reason) | 结束有效模式与未完成切换，取消自动回滚激活 |
| getInputControlStatus(peerId) | 查询鼠标/键盘能力、权限、统一焦点及按下释放状态；不提供独立键盘共享开关 |
| getPeerUsageSnapshot / subscribePeerUsageEvents | 返回目标、期望/实际模式、切换进度与恢复结果 |
| discoverDisplayPeers / cancelDiscovery | 枚举已发布的显示接收能力，不发起配对 |
| requestDisplaySession(peerId, config, requestId) | 发起请求并执行预检，未获允许前不创建虚拟屏 |
| respondToDisplayRequest(requestId, allow) | 接收端允许/拒绝，校验请求仍有效 |
| cancelDisplayRequest(requestId) | 取消并撤销晚到响应 |
| setDisplayLayout(sessionId, generation, layout) | 提交布局并返回系统最终确认拓扑 |
| presentReceiverWindow(sessionId) | 恢复既有接收窗口，不创建第二会话 |
| setReceiverPresentation(sessionId, mode, screenId) | 选择窗口/全屏与目标物理屏 |
| stopDisplaySession(sessionId, reason) | 任一端可调用，幂等，执行资源回收 |
| retryDisplayCleanup(sessionId) | 只回收该会话拥有的残留资源 |
| getDisplaySessionSnapshot / subscribeDisplayEvents | 各入口获取一致状态与结果 |

显示操作属于设备用途协调器的子操作；GUI 不得绕过 `switchPeerUsageMode` 单独启动显示或输入路由。操作必须异步执行，GUI 主线程不进行网络等待、虚拟屏创建、采集、编解码或清理阻塞。取消与开始、结束与首帧、页面切换与晚到事件均需有代次保护。

### 13.3 会话快照最少字段

设备用途快照：`peerId`、`peerName`、`baseConnectionId`、`baseConnected`、`originalInputRole`、`originalInputDirection`、`operationId`、`operationGeneration`、`selectedMode`、`effectiveMode`（none/input/extended）、`targetMode`、`usageState`、`switchStage`、`inputCapabilities`、`inputPermissionsReady`、`inputFocusOwner`、`pressedInputsReleased`、`oldModeStopped`、`rollbackResult`、`reasonCode`、`availableActions`、`permissions`。

显示子快照：`sessionId`、`requestId`、`generation`、`displayEpoch`、`localDisplayRole`、`state`、`virtualDisplayId`、`confirmedLayout`、`streamConfig`、`receiverScreenId`、`presentationMode`、`firstFramePresented`、`inputEnabled`、`inputRoutingSuspended`、`cleanupStatus`。两份快照通过 peer/operation/session 关联；持久设备连接状态不等于有效使用模式。模式枚举建议统一为 input/extended；如实验代码已使用 mouse 标识，集成时需明确映射并核实它表示完整键鼠共享，不能只改 UI 标签。

统计数据可为空，携带有效性标记和采样时间。没有呈现确认时 `firstFramePresented` 不得由“解码成功”推断；没有有效采集时间时不返回伪造 latencyMs。

### 13.4 错误与资源所有权

至少提供：UnsupportedPlatform、UnsupportedPeerVersion、InputCapabilityIncomplete、InputIsolationUnsupported、InputReleaseFailed、InputPermissionDenied、ModeConflict、SwitchFailed、RollbackFailed、PeerBusy、PeerRejected、RequestExpired、PermissionDenied、SessionUnavailable、NetworkUnavailable、IdentityChanged、DisplayCreationFailed、LayoutRejected、DecodeFailed、PresentationFailed、Congestion、ConnectionLost、CleanupFailed。

每项错误映射用户文案、可重试性与恢复动作；原始技术日志仅在详情中展示。资源绑定设备身份、会话和拥有进程，清理不能依据可变设备名误删其他输出。接收端确认结束与本地虚拟屏确认释放分别记录，不能相互替代。

## 14. 体验与发布验收目标

以下是建议的 P0 发布门槛，尚未实测达标；需在限定 OS/GPU/桌面组合上记录结果后批准发布。

| 指标 | 建议门槛/方法 |
| --- | --- |
| 交互响应 | 点击后 100ms 内显示明确反馈，过渡不等待后端执行完毕 |
| 请求等待 | 应用内授权请求 30 秒过期，可取消；系统权限操作单独计时 |
| 首帧 | 对方允许且系统权限就绪后，正常 LAN 场景 10 秒内看到首帧；超时明确失败并清理 |
| 显示目标 | 1080p SDR，目标 30fps；用持续运动内容验证，不能用静止画面更新数推导 |
| 画质 | 文档、代码、网页小字无裁切/比例错误；按具体编码档位记录可接受性 |
| 稳定性 | 每个发布方向连续使用 60 分钟，窗口/全屏各覆盖；无持续内存增长、崩溃或遗留副屏 |
| 结束 | 正常停止目标 5 秒内确认本地资源释放；超时转 CleanupRequired，不伪报完成 |
| 异常 | 检测到断线即覆盖失效画面；从异常发生到清理目标不超过 15 秒，需注入故障实测 |
| GUI 布局 | 主窗口 100%、125%、150%、200% 缩放下无覆盖、主操作可见，切换状态不改变固定尺寸 |
| 可访问性 | 键盘可遍历操作，焦点可见，图标有名称，状态有文字，不用颜色独自传递信息 |

Windows/Linux 共享布局不代表共用系统后端。Mac ↔ Mac 以及 Mac ↔ Ubuntu 每个方向分别验收；Ubuntu 认证记录应包含桌面/会话、合成器、GPU、驱动和编解码路径。Windows 与其他 Linux 环境未通过前不宣传全面支持。

## 17. 尚需确认的产品决策

已确认的核心需求：同一目标选择“键鼠共享 / 扩展屏幕”，两种用途互斥；键鼠共享整体提供本机鼠标和键盘，扩展屏幕显示本机新增桌面区域；模式切换仅位于设备列表和屏幕排列，首页和连接方法保持现有设计。以下其余建议和实现边界需在 M0 确认：

| 待确认项 | 本文建议 | 对范围的影响 |
| --- | --- | --- |
| 首版实际系统组合 | Mac ↔ Mac、Mac ↔ Ubuntu，Windows 后续 | 每一方向需要相应设备与后端认证；现有证据未覆盖 Mac ↔ Mac |
| 接收端输入 | P0 只显示画面，P1 单独授权控制 | 若首版必须回传输入，将新增输入安全和映射工作 |
| 输入隔离与恢复实现 | 同设备用途互斥，统一协调切换 | 核实按目标隔离、释放确认及授权有效性；不得降级为并行用途 |
| 默认接收方式 | 每次允许、默认窗口，用户再选全屏 | 永久允许和自动全屏需另做授权及误触设计 |
| 初始显示档位 | 固定 1080p SDR，目标 30fps | 自动匹配分辨率与 HiDPI 会增加协商和重建需求 |
| 自动恢复 | P0 手动重试；锁屏后重新允许 | 若首版需要无感重连，需补充恢复窗口与授权有效期设计 |
| 控件视觉细节 | 仅在设备列表与排列属性区增加紧凑用途切换 | 复核原页面对齐、局部状态占位与国际化，不改首页布局 |

产品评审后更新版本和决策记录；未确认项不应被实现者视为已经获得最终批准。
