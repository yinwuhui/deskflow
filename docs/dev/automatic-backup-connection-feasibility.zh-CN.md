# 自动建立备用连接：底层可行性评审

日期：2026-10-22。依据：需求草案 v0.2（用户确认不要求旧客户端兼容）及当前工作区源码。本文为静态代码与平台 API 评审，不代表完成双机验证；不修改运行行为或现有需求文档。

## 结论

技术上有条件可行。现有认证字节通道、心跳、单活动会话、代次隔离和输入释放可复用；但现有自动模式不能直接通过默认开启或增加 GUI 开关满足本需求。需要新增按 Peer 的连接编排、首次信任接入、版本化管理协议、动态端点和策略、结构化 IPC，以及保留普通局域网多设备能力的入口。

建议按需求阶段 A 先验证平台与协议，再开发 B/C/D。Mac ↔ Mac、Mac ↔ Linux 双向 RFCOMM 发现、配对及连接仍是实际发布门槛；暂不具备承诺全部 P0 已可交付的证据。

| B06 恢复 | 心跳、旧 epoch 拒绝、有界队列、回压、输入释放 | 主要复用；修改首选通道、恢复选择、禁用策略和按 Peer 的核心状态；工作量中 |

## 必须先解决的设计问题

### 1. 首条连接必须从一开始就具备管理能力

普通网络直接使用核心 TLS/键鼠协议；单蓝牙经 RfcommBridge 桥接核心流；自动模式在外层使用 TlsChannel + DFF1，再桥接核心。三种不是可随时互换的同一种会话。

当前 AutoTransport 启动要有 32 字节可信指纹、有效蓝牙地址及客户端网络主机；服务端接管原网络端口并把核心改为回环监听。不能在普通连接已经工作后直接插入 AutoTransport，也不能向旧输入流发送能力 JSON。

已确认当前处于开发阶段，不要求旧客户端兼容。因此建议统一网络和蓝牙的版本化管理封装，沿用认证通道及逻辑核心连接，从第一条通道开始支持协商；不额外维护旧版识别、双入口或自动回退路径。

统一入口仍须支持单通道启动、首次信任与多设备分流。首条已认证通道形成后异步交换端点；备用失败不会销毁活动通道。发现服务的 UUID、网络服务声明和客户端握手需同步更新，但不需要在旧输入协议中偷插消息。

关闭自动备用应保留当前活动通道及其管理封装；不能为了退出自动模式重新启动核心或切回旧协议。

### 2. 首次信任不能依赖预先已有指纹

现有 TlsChannel 构造时固定对端指纹；未知对端不能走完现有认证通道。因此需加入待确认身份状态，或复用既有网络信任确认后再进入管理流程。蓝牙首连也必须可完成同等强度的身份确认。

信任确认要绑定当前握手、证书、Peer 和操作代次；未确认前不启用控制或交换可用备用端点。不能仅靠设备名称、系统配对或未经认证的端点声明关联电脑。

建议 PeerId 为本地稳定记录 ID，证书是当前授权身份的引用；首版证书变化要求显式确认。复制同一通信证书的两台电脑无法仅凭该证书可靠区分；需要防止克隆证书被当作两个独立可信 Peer。

现有 SecureSocket 将指纹作为全局 IPC 字符串发送，FingerprintDatabase 只保存列表。多设备下需将已认证指纹绑定到具体 socket/client/Peer，不能用“最后收到的指纹”关联备用。

### 3. 多设备兼容要求按 Peer 接入，不能启动多个核心

现有自动模式一份 AutoTransport 只有一个 host、一个 pin、一份 FailoverSession，且启动时将整个服务端核心改为回环监听。直接开启会排除原来从外部直连核心的传统客户端。

即使不兼容旧客户端，仍需保留同一键鼠核心和布局，让当前版本的普通网络 Peer 与一个受保护 Peer 的逻辑连接同时接入。可采用公共接入分发器或独立受管理监听器，但须明确原监听器、受管理入口和内部核心的端口归属、认证责任及身份映射。

不要为每个 Peer 启动一个完整键鼠核心：这会竞争事件捕获、光标、布局及全局 IPC。应复用同一个服务端核心，扩展连接接入与按 Peer 状态。

Server 当前 Connected/Listening 为聚合状态；任何客户端连接都可能发 Connected。备用目标恢复必须由目标核心会话握手事件确认，不能继续用全局 connectionState 驱动 FailoverSession。

### 4. 首选与故障选择需要显式语义

FailoverSession 初始 preferred 固定网络，活动通道断开后将偏好设为另一条。这不完全符合“用户首连优先；故障且两条均可用才优先网络”。需区分 initialTransport、activeTransport、recoveryPreference，连接先后不能决定用户首选。

每个会话最多一条活动输入流。旧输入和旧代次清理可沿用，但禁用备用、切换目标、唤醒、进程重启必须统一使操作代次失效。仅使用布尔 active 不能覆盖同一设备取消后立即重试的晚到回调。

### 5. 发现不是认证，系统配对不是备用就绪

BluetoothDiscovery 当前服务发现过滤的是旧单蓝牙 UUID；AutoTransport 使用另一个 UUID。需按协议指定服务过滤和记录版本，不能把旧服务扫描结果当新管理入口。

无可用蓝牙地址时，可尝试以新服务记录中的短期随机定位信息筛选候选，再由 TLS 身份验证最终确认。该方法需要两机验证 macOS/Linux 的 SDP 字段发布、发现、可见性及缓存表现；定位信息不构成身份凭证。候选不唯一时要求选择，不能对所有同名电脑批量配对。

Qt 6.8 文档说明 macOS 不能通过 QBluetoothLocalDevice 改变蓝牙电源或可发现模式，不能假设后台扫描总能找到电脑。发现不可用时的系统准备指引必须存在。

Linux 当前 confirm/providePin 是空实现，依赖系统 BlueZ 默认代理。建议首版锁定“有桌面系统代理”的支持范围，缺少时返回明确动作；若要求应用内完整确认，则需实现 Agent1，属于新增平台能力。

### 6. IPC 必须先具备完整消息和本地授权边界

IpcServer 当前 readAll 后按换行处理，半包会被丢弃，尾部残片也不保留。增大载荷或引入 JSON 会放大问题。应增加每个 socket 的接收缓存、消息大小上限、明确帧格式、字段校验及请求关联。

现有本地 socket 使用 WorldAccessOption；当前主要命令是 stop。扩展到信任、PIN、策略、端点和动作应答前，应按运行模式限制连接者并校验本地身份/授权；仅给消息加 sessionId 不能授权任意本地进程处理用户动作。

快照由核心连接服务保存，GUI 在握手后主动读取。排队重放历史字符串不是完整快照机制。状态 revision、操作代次和传输 epoch 是不同概念，应分别维护。

### 7. 默认开启、剪贴板与迁移尚需产品定案

当前限制通过 ServerApp 加载 Config 时施加，属于全局服务端限制。若直接默认开启，会影响未选择备用的普通局域网电脑，和多设备兼容目标冲突。

首版需要明确：只限制受保护 Peer，还是所有电脑接受同一上限。前者需要按会话的剪贴板限制；若要求大剪贴板保持原体验，还需数据调度/取消及会话归属设计。恢复时不补发旧剪贴板也需验证核心缓冲，不能只确认传输缓存已清空。

迁移要查看原始设置中 autoFailover 是否存在，不能读取带默认值的 bool 后猜用户意图；明确 false 保留关闭。历史没有留下显式选择的情况无法恢复真实意图，应标记为继承默认并提示，不能声称已还原旧偏好。新增 Peer 存储还要纳入 Settings 的有效键/组及清理逻辑。

## 建议的职责划分

- ConnectionCoordinator：按 Peer 编排首连、备用、恢复与停止；集中管理操作代次和策略交集。
- PeerStore / TrustAdapter：身份、证书引用、端点缓存和迁移；不重新实现密码学。
- ManagedLink：TlsChannel 上的版本化管理/数据协议，区分能力、端点、策略和输入数据。
- Network / Rfcomm Connector：监听、候选拨号、发现、退避；错误按通道隔离。
- FailoverSession：一个 Peer 的活动选择、epoch、回压与逻辑核心连接；保留已有核心安全规则。
- PlatformActionBroker：蓝牙权限、配对、系统代理，异步动作及取消。
- ConnectionSnapshot / IPC Adapter：完整状态、revision、动作和诊断，不让 GUI 解析自然语言日志。

工作线程和 Qt 主事件线程之间通过消息/队列交换不可变状态；不要在 GUI 做同步扫描，也不要让网络线程直接操作 GUI。

## 用户已确认的决策与剩余设计项

- 不考虑旧客户端兼容，统一当前版本的连接封装。
- 关闭自动备用后保留当前通道自身的自动重连；主动断开则停止选定 Peer 的全部重连任务。
- 剪贴板改为按 Peer 限制或调整传输策略，不保留影响所有 Peer 的全局备用限制。
- “断开连接”仅作用于所选 Peer，“停止共享”停止全部 Peer。

剩余设计项：首次信任确认方式、证书变更/复制处理、受保护 Peer 的剪贴板上限与调度方案、统一 wire format、服务定位信息，以及 Linux 桌面/配对代理与 X11/Wayland 的明确支持矩阵。

## 验证顺序与开发门槛

A：最小双机验证。两种组合交换角色，验证 TCP/RFCOMM、UUID/SDP 定位、首次配对代理、首次身份确认；验证统一管理封装和未知备用地址首连。此阶段前不承诺无线性能或工期。

B：复用现有测试框架做单通道启动、端点更新、动态补建、双方策略、幂等取消及攻击/异常帧；确认备用失败不影响首连。增加按 Peer 核心事件和多设备兼容测试。

C：结构化 IPC、快照重连、存储迁移、权限动作与拒绝行为；验证半包/粘包、过期应答和本地客户端授权。

D：接入首页真实状态和操作，不使用模拟状态代替能力探测。

E：执行需求矩阵和持续运行。没有两台 Mac 和 Linux 实机就不能完成本需求全部验收；本机 TCP 模拟通过只能证明逻辑，不证明射频、系统权限或配对。

此次仅完成静态评审，未重新运行测试、修改源码或创建提交。
