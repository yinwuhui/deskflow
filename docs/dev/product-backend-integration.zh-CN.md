# 设备用途后端集成记录

更新：2026-10-25。依据 `docs/product/extended-display-requirements.zh-CN.md` v1.2。

## 当前结论

已实现统一用途事务、显示子服务、媒体进程监督、按目标输入暂停/恢复协议及核心 IPC。编译和自动测试通过不等于产品发布验收；发现/信任与显示授权控制通道、布局操作、应用启动装配和 Mac ↔ Ubuntu 实机双模式切换仍未全部贯通。

本次按当前开发版本实现，没有新增历史版本适配分支。能力检查用于判断运行平台、实际输入权限、认证身份、路由隔离及资源状态；不会把仅有连接当作完整能力。

## 组件与职责

| 组件 | 已实现职责 |
| --- | --- |
| `UsageCoordinator` | 每目标 `none/input/extended` 互斥事务，预检、授权、释放、停止、启用、取消、回滚、超时与清理屏障 |
| `PeerUsageService` | 异步 JSON 命令、认证设备注册、统一快照/事件、单扩展会话预留、只读输入状态 |
| `UsageDisplayBridge` | 关联用途操作和显示请求；授权后等待旧输入停止；真实呈现确认才激活扩展；结束显示不自动恢复输入 |
| `DisplayService` / `Coordinator` | 显示授权、权限、代次、准备、首帧、结束及资源清理；GUI 直接开始显示被拒绝 |
| `InputRouteAdapter` | 将用途效果转成输入核心 IPC；校验 peer、操作代次、序号及结果；轮询确认、超时撤权 |
| `CoreInputChannel` | 复用同用户核心本地 socket 与当前构建版本握手；有界消息与缓冲；不接受 GUI 指定地址或程序路径 |
| `Server` / `ClientProxy1_0` | 按认证证书指纹暂停一个目标；屏蔽边缘、跳转和键盘广播绕过；确认恢复后提交路由 |
| `ServerProxy` / `Client` / `Computer` | 在受控端处理输入探测、暂停、恢复；暂停强制释放合成键鼠；恢复后等待统一焦点进入 |
| `ResourceJournal` / `MediaSupervisor` | 原子保存资源所有权、异步进程监督、可信生命周期事件、残留检查和已验证清理 |
| `busymouse-display-viewer` | Qt 独立接收窗口、比例保持、选屏/全屏、原生绘制回调确认首帧 |

应用侧取得 `PeerUsageService::applicationService()` 时，显示桥、输入适配器和本地核心通道一同装配。它不会自动信任设备、打开输入权限或创建副屏。设备和能力须由真实认证/探测入口注册；目前不能据此认为启动发现已完成。

## 对外用途契约

命令信封为 `{id, operation, args}`，异步返回 `commandFinished`。快照变更通过 `snapshotChanged` 发送。`subscribePeerUsageEvents` 返回初始快照；应用绑定信号获取后续事件。

- `queryPeerUsageCapabilities(peerId)`
- `selectPeer(peerId)`、`selectUsageMode(mode, peerId?)`
- `startPeerUsage(peerId, mode, operationId, options?)`
- `switchPeerUsageMode(peerId, targetMode, operationId)`
- `cancelPeerUsageOperation(peerId, operationId, operationGeneration)`
- `stopPeerUsage(peerId, reason?)`，用户入口只接受 `UserStopped`
- `getInputControlStatus(peerId)`
- `getPeerUsageSnapshot(peerId)`、`subscribePeerUsageEvents(peerId)`

`mode` 为 `input` 或 `extended`，不接受 `mouse`。P0 的 `options` 只能省略或为空对象；独立键盘开关、未知字段及旧的 `setMouseSharingOptions` 均被拒绝。

操作 ID 是非零的 16 字节小写十六进制串；操作代次、快照修订号使用十进制字符串，避免 JSON 数字精度损失。协调器保留最近 128 个已使用操作 ID，拒绝重放。适配器回调为 C++ 内部入口，不能作为 GUI 命令调用。

用途快照提供：设备 ID/名称、操作 ID/代次、期望/实际模式、状态/阶段、输入能力与权限、统一焦点、释放确认、旧模式停止、恢复结果、原因及可用动作。未知焦点返回 null；没有真实统计时不填入虚构帧率或延迟。

## 切换屏障

键鼠 → 扩展：

1. 预检与显示授权期间旧键鼠仍有效。
2. 显示子服务取得对方许可及采集许可后，停在 Authorizing；此时没有创建副屏或启动媒体进程。
3. 撤回目标输入，回到本机焦点；等待受控端执行释放并返回精确确认。
4. 确认该目标旧路由停用，并确认其他路由不会冲突，才解除显示准备屏障。
5. 虚拟屏准备与原生呈现都确认后激活扩展。
6. 停旧后准备失败，先验证清理；仅在原控制连接、权限仍有效且用户没有停止时恢复输入。

扩展 → 键鼠：先探测完整输入与许可，再结束显示；验证本会话副屏移除后恢复目标路由。恢复失败两种用途都不启用，不用旧显示授权重建副屏。

输入恢复是两步：受控端确认恢复准备，然后发送端提交边缘路由。接收端仍处于本机焦点；下一次正常跨屏进入时才整体接受键盘和鼠标。独立键盘广播不能绕过已管理目标的焦点约束。

释放/停止输入超过 5 秒进入清理屏障。适配器单次核心操作最多等待 4 秒；启动及清理等其他协调阶段有上限。系统权限等待由相关许可流程处理。未经释放或资源清理确认，不能仅凭进程退出/消息发送成功宣告完成。

## 输入核心协议与 IPC

当前开发协议通过认证连接中的 `BIC1=1` 选项交换输入控制能力。证书身份必须来自底层已验证的 SHA-256 指纹，不使用名称或地址替代。

| 消息 | 内容 |
| --- | --- |
| `DICV` | 32 位能力协议号，目前为 1 |
| `CICM` | 32 位单连接递增序号 + 8 位动作：0 暂停，1 恢复准备，2 只读输入就绪探测 |
| `DICA` | 同一序号 + 8 位结果：0 失败，1 已暂停释放，2 已准备恢复，3 输入后端已就绪 |

暂停先关闭后续注入，再释放逻辑按键和已合成的鼠标按钮，即使当前正在拖拽也执行。只读探测不改变焦点。序号 0、倒序和同序号不同动作不会执行；同序号同动作可重复返回原结果。发送端只接受当前序号与当前动作匹配的确认。

本地 IPC 为 `inputControl=<JSON>`，返回 `inputControlResult=<JSON>`；需要已有同用户 socket 认证和构建版本握手。字段为 `id/kind/peerId/sequence/operationId/operationGeneration/enabled`。kind 包括 `status/probe/suspend/resume/commitResume`。核心在输入事件线程执行命令，Qt socket 线程只负责接收和回传。

`acknowledged` 表示指定暂停/恢复动作成功，`acknowledgementReceived` 也能表达收到失败确认；`inputPermissionsReady` 仅来自本次实际后端就绪探测。另返回目标暂停、焦点、已用序号及其他路由是否已隔离。

## 验证与边界

Ubuntu 完整构建及 114 项 CTest 通过。输入协议的新增断言包含在现有 Qt 测试程序中，CTest 项数不等于断言/用例总数。

已覆盖：

- 设备选择不启动、拒绝独立键盘参数、完整输入许可、回到本机焦点的释放屏障；
- 对方拒绝保留旧输入、授权后不提前创建、首帧前不激活、清理前不恢复；
- 取消、断线、过期回调、操作 ID 重放、释放和启动超时；
- 协调器 → 输入适配器的异步确认流程，及错设备/错代次结果被忽略；
- 实际输入协议代理 → `Client` → `Computer` 路径，使用记录平台替身验证拖拽释放、暂停拦截及焦点恢复；
- 真实 `Server` 只暂停指定证书目标、保留另一连接、确认前不能提交恢复。

这些测试没有替代 Mac/Ubuntu 系统权限、硬件键鼠、物理焦点及真实副屏的跨机产品验收。原阶段 B 的媒体实验也不能替代此次完整模式切换验收。

## 尚需完成

1. 将设备发现、现有信任库、角色独立的能力公告、显示请求/允许/拒绝控制通道接入用途服务。实验媒体握手不能替代用户本次显示同意。

4. 完成输入权限变化、系统锁屏/睡眠、信任撤销与双端用途事件联动。当前探测针对已启用的核心后端，仍需完整实机撤销场景验证。
5. 实现系统确认后的布局、接收窗口恢复/呈现偏好、完整窗口状态、平台能力探测与打包。
