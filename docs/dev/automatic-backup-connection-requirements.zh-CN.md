# BMouse 自动建立备用连接需求文档

- 状态：需求草案 v0.2，已补充 2026-10-22 用户确认；不代表下述接口已经实现。
- 日期：2026-10-22。
- 首版平台：**Mac ↔ Mac、Mac ↔ Linux**，已由用户确认。
- 需求来源：首页蓝牙交互讨论，以及“用户只建立一种连接，另一种由两端自动协商建立”的产品目标。
- 本次交付仅为需求文档，不修改软件行为、连接配置或系统权限。

## 1. 产品目标与范围

用户选择“局域网”或“蓝牙”建立首条连接。首条连接确认对方身份后，两端 BMouse 自动协商、补建另一条连接，使其成为可用的备用通道。当前通道故障时，使用备用通道重新建立键鼠会话。

首页只保留两个首连入口：局域网、蓝牙。另提供一个默认开启的选项：

> **自动建立备用连接**  
> 连接成功后，自动尝试建立另一种连接；当前连接中断时，自动恢复。

该选项同时控制自动补建备用通道和故障时自动使用备用通道，不再向用户呈现独立的“自动切换”第三种首连方式。

### 1.1 首版必须实现

1. 局域网首连成功后，自动发现、关联并尝试建立同一台电脑的蓝牙备用通道。
2. 蓝牙首连成功后，自动获取对方的可用网络端点并尝试建立局域网备用通道。
3. 已授权、已配对、已信任的设备，后续使用不要求重复手动输入第二种连接的地址。
4. 蓝牙首次授权、首次配对和首次电脑身份确认，允许出现必要的用户操作。
5. 第二条通道失败、被拒绝或不可用时，第一条连接继续工作。
6. 首页准确展示当前通道、备用通道状态和用户需要完成的操作，保持布局稳定。
7. 两条通道最多承载一个活动键鼠会话，断线切换不重放旧输入。

### 1.2 首版边界

- 蓝牙及自动备用功能只面向一个已选定的对端；不把所有已发现或已信任电脑自动加入备用连接。
- 传统局域网多设备共享继续可用。多设备场景下需明确选择一个备用目标；未选定时保持局域网工作并提示“选择一台电脑启用备用连接”。
- 不要求两条通道同时可用。无可达网络、无蓝牙适配器、蓝牙关闭或未授权均为正常降级状态。
- 故障恢复允许短暂中断；不承诺会话无缝迁移，不恢复旧拖动或旧点击。
- 首版不主动从健康的蓝牙连接切回局域网；网络恢复后作为备用。
- 不包含 Windows、BLE/HID 模式、带宽聚合、多蓝牙对端、证书自动换信任、文件传输或远程开机。
- 当前处于开发阶段，不要求兼容旧客户端或保留旧协议入口；可统一修改网络与蓝牙的管理封装。普通局域网多设备能力仍须保留。

## 3. 用户流程

### 3.1 从局域网开始

1. 用户选择工作角色与目标电脑，点击“连接”或“开始共享”。
2. 完成现有局域网连接及必要的电脑身份确认，键鼠立即可以使用。
3. 首条可信连接建立后，双方交换能力和备用策略。
4. 双方允许且具备蓝牙条件时，交换蓝牙服务定位信息，定向查找对应电脑。
5. 若首次授权或配对需要确认，首页显示一次待办，用户可以稍后完成；局域网继续工作。
6. 建立蓝牙通道并验证其属于同一可信 Peer，完成协议与健康检查后标记为“备用已就绪”。

### 3.2 从蓝牙开始

1. 用户选择附近运行 BMouse 的电脑，按需完成配对与电脑身份确认。
2. 蓝牙键鼠连接成功后即可以使用，不等待网络探测。
3. 双方交换可用网络端点和监听能力，后台逐个探测少量候选地址。
4. 网络通道认证为同一 Peer 并通过健康检查后，标记为局域网备用。
5. 若没有可达网络，保持蓝牙工作；网络变化后按节流策略重新尝试。
6. 用户明确选择的首条健康通道保持活动，不因网络随后可用而立刻切换。

### 3.3 故障与恢复

1. 明确断开立即处理；静默故障由心跳超时确认。
2. 关闭旧键鼠会话，清理合成按键与鼠标按下状态；停止远端控制，控制回到本机。
3. 如果另一条认证通道可用，建立新代次的键鼠会话。
4. 只有核心握手完成后，才报告“已通过另一种连接恢复”。用户正常跨屏继续，不自动把光标送回远端。
5. 旧通道恢复后作为备用。两条都不可用时后台重试，停止或断开操作可随时取消。

### 3.4 关闭开关与主动断开

- 关闭“自动建立备用连接”：取消补建/扫描/配对待办、备用重试及跨通道切换，关闭该会话未承载输入的备用通道；保留当前活动通道及其自身的自动重连。
- 如果蓝牙已经成为活动通道，关闭开关也不应断开它或强制切回网络。
- 任意一端关闭此策略，双方协商结果都应停止使用自动备用功能；不能由另一端远程重新开启。
- 点击“断开连接”：只停止选定 Peer 的两条通道及全部恢复任务，其他 Peer 继续工作。点击“停止共享”：停止全部 Peer 及其连接任务。两者均不能因为默认开关开启而自动重新连接。
- 取消一次授权/配对，不等同于撤销已有电脑信任，也不移除系统既有配对。

## 4. 底层能力需求

### B01 统一电脑身份与通道关联（P0）

- 建立稳定 `PeerId`，显示名称只用于展示，IP/蓝牙地址只用于定位；均不能单独证明电脑身份。
- 首条通道通过既有信任流程得到对端证书身份。第二条通道必须证明属于同一 Peer 和同一已授权身份。
- 已认证信息才能更新端点缓存；广播内容和设备名称只能作为查找线索。
- 证书变化进入明确的重新确认流程；不得自动信任网络或蓝牙上报的新证书。
- 区分应用签名证书与 BMouse 通信证书：前者关联系统授权，后者验证远端电脑，不得混用。
- 不发送私钥，不通过“已配对”替代 BMouse 身份验证。
- 如果原有局域网会话未启用 TLS 或未验证对端身份，不在其上自动交换备用端点或增加信任。保持原连接行为，提示用户显式启用加密与身份校验后才能准备备用连接，不静默改写安全设置。

### B02 双方能力和策略协商（P0）

- 交换协议版本范围、平台、可用传输类型、角色、可监听/可拨号能力、备用策略、限制及会话实例。
- 对端愿意接受某通道，且本端允许建立时，该通道才允许补建；有效策略是双方授权范围的交集。
- 为会话指定唯一协调者。沿用接收键鼠的客户端控制激活代次；共享端准备监听与授权，不同时发起重复激活。
- 工作角色决定连接方向，不能假定所有系统可对称监听；发现对端不能满足所需方向时降级并返回原因。
- 不要求兼容旧客户端。当前版本未编译蓝牙或能力不足时保持可用单通道，明确显示备用不可用原因。

### B03 运行中端点交换与补建（P0）

- 首连不依赖备用地址，不等待蓝牙扫描或网络备用握手。
- 通过已认证控制消息交换实际监听地址/端口、服务版本/UUID及必要的发现线索。
- 不保证所有平台都能提供可直接使用的本机蓝牙地址。缺失时支持服务发现和短期会话定位信息，再通过 TLS 验证身份。
- 无法唯一定位设备时返回“需要选择电脑”，不能只凭同名设备自动配对。
- 网络候选优先使用用户选定网卡与可用局域网地址；过滤回环、无效地址，限制候选数与尝试端口，不执行通用端口扫描。
- IPv6 link-local 的作用域必须在本机路由上下文解析，不直接使用对方网卡的 scope ID。
- 端点有有效期与代次，处理 DHCP、网卡切换、休眠及蓝牙适配器变化；失败候选可失效而不清除已确认身份。
- 新模式的网络/蓝牙服务发现必须与旧的单通道入口区分，不能错误使用旧服务 UUID 或旧端口握手。

### B04 权限、配对与用户动作代理（P0）

- 枚举“不支持、适配器关闭、权限未知、被拒绝、可用、缺少系统配对代理”等状态。
- 默认开启开关表示允许尝试备用功能，不表示系统权限已经授予。
- 在用户实际连接并确认对端后，才触发相关首次权限流程；拒绝后不反复自动弹出。
- 配对动作包含确认码、输入 PIN、查看配对码、取消和超时；必须等待必要的用户确认。
- 两端都能收到本端待完成的操作；一端确认不能代替另一端的系统确认。
- GUI 与核心应明确权限请求者和实际蓝牙操作者，避免 GUI 显示已授权而执行进程仍无权限。
- Qt 蓝牙操作保留在线程约束允许的事件线程中，所有 GUI 调用异步返回。
- Linux 首版采用系统 BlueZ 代理还是应用代理需验证并锁定。当前 Linux `confirm` / `providePin` 没有应用内实现，不得对 GUI 报告其已支持直接确认。
- 取消后忽略晚到回调；即使系统最终完成配对，也不能恢复用户已经取消的连接操作。

### B05 统一连接编排器（P0）

- 提供首连、能力协商、备用准备、策略修改、主动停止与故障恢复的统一入口。
- 活动连接与备用准备使用独立生命周期和错误范围；备用错误不能上升为使活动连接退出的致命错误。
- 支持运行中增加/移除该会话的备用通道，避免为补建备用连接重启正在工作的核心。
- 同一 Peer 及同一会话至多一个活动输入会话、一个备用通道。并发和重试操作必须幂等。
- 设置改变、断开、切换目标和程序退出时统一取消任务；所有回调关联操作 ID 和代次。
- 双方同时操作、重复发现、进程重启和过期回调不能建立第二个键鼠会话。

### B06 备用就绪与故障恢复（P0）

- “已就绪”必须经过传输连接、身份验证、版本协商、角色匹配及有效健康检查；操作系统配对成功不等于备用就绪。
- 两条连接独立健康检测；备用损坏不触发当前活动连接切换。
- 正常情况下保持用户首选且已经连接的通道；故障恢复且两条都可用时才按约定优先局域网。
- 保留现有单调递增 epoch、旧代次拒绝、有界队列、回压及无输入重放规则。
- 重建核心会话前清理旧输入状态。恢复后不自动续接拖动、点击或旧剪贴板数据。
- 在关闭开关或主动断开时停止故障切换；开关开启但备用尚未就绪时，不得向 GUI 声称“已受双通道保护”。

### B07 持久化与迁移（P0）

- 保存全局默认开启值，以及按可信 Peer 的显式开启/关闭策略；用户的显式关闭跨重启保留。
- 保存身份与传输关联、最近有效端点、服务版本及最后验证时间。密钥沿用既有证书存储。
- 本地撤销信任后立即停止对该 Peer 的自动补建，清除对应关联；不隐式删除系统蓝牙配对。
- 对端关闭策略属于运行时协商结果，不覆盖本端用户原有偏好。
- 迁移现有 `autoFailover`、`bluetoothPeer`、`peerFingerprint` 配置；旧的显式关闭不能被“新默认开启”覆盖。
- 无法区分旧版缺省值与用户显式选择时，须制定并测试迁移规则，不能直接按旧布尔默认值猜测。
- 普通局域网主机、端口和网卡配置继续保留；备用失败或关闭不清空它们。

### B08 GUI 结构化状态与诊断（P0）

- 提供活动连接和备用连接的独立状态、原因、下一次尝试时间，以及需要用户处理的动作。
- GUI 重新打开或重连 IPC 时可取得完整快照，不能只依赖增量事件。
- 错误须区分不支持、对端关闭、权限拒绝、适配器关闭、未配对、身份不匹配、地址不可达、协议不兼容、取消及超时。
- “开始连接已受理”“传输已连接”“对端已认证”“核心会话可用”分别报告。
- 日志带会话/操作/通道/代次和耗时，默认不记录输入内容、配对 PIN 或完整敏感身份材料；本需求不新增遥测上传。

## 5. 拟新增的数据模型和接口契约

以下名称为建议，可在技术设计中调整；语义与错误边界为需求约束，不应直接视作已有 C++ API。

### 5.1 主要模型

| 模型 | 最低字段及语义 |
|---|---|
| `PeerIdentity` | `peerId`、显示名称、已确认身份引用/证书指纹、信任状态；名称变化不产生新电脑 |
| `PeerCapabilities` | 协议版本范围、平台、角色、传输支持、监听/拨号能力、运行实例、策略与限制 |
| `EndpointCandidate` | 通道类型、地址/端口或蓝牙服务定位、优先级、有效期、来源及其认证会话 |
| `ConnectionPolicy` | `initialTransport`、`autoBackupRequested`、策略来源；不把用户偏好与协商结果存成同一个布尔值 |
| `ConnectionSnapshot` | `sessionId`、`peerId`、`revision`、活动通道及核心状态、备用状态、有效策略、原因、待办和限制 |
| `UserAction` | `actionId`、会话/操作/Peer 绑定、动作类型、确认内容、截止时间及是否可以稍后处理 |
| `OperationResult` | `operationId`、是否成功、错误码、作用范围、是否可重试；与“连接已经可用”分离 |

### 5.2 GUI → 核心/连接服务

| 建议接口 | 作用与约束 |
|---|---|
| `getTransportCapabilities()` | 获取本机支持、权限、适配器及配对代理状态；不隐式弹权限窗口 |
| `startConnection(peerOrTarget, role, initialTransport, policy)` | 只凭首连目标即可启动，返回操作 ID；不要求预填备用地址 |
| `setAutoBackupPolicy(peerId, enabled)` | 保存本端策略并协商生效；返回生效状态，不能无提示中断活动连接 |
| `getConnectionSnapshot(sessionId)` | 返回当前完整快照及版本号，供首次显示和 IPC 重连恢复 |
| `discoverPeers(transport, scope)` / `cancelDiscovery(operationId)` | 有范围、期限、结果去重及取消；不把所有扫描结果都解释为可连接 BMouse |
| `prepareBackup(sessionId)` | 首连可信后由编排器自动触发，也允许用户手动重试；重复调用幂等 |
| `requestUserAction(actionId)` | 用户点击授权/配对入口后推进本地系统流程；缺少当前有效动作时拒绝 |
| `respondToUserAction(actionId, response)` | 接收确认/拒绝/PIN等；校验其会话与代次，拒绝过期回答，不记录 PIN |
| `retryBackup(sessionId)` | 只重试备用通道，不重启正常的主连接，不重复强弹被拒绝的系统授权 |
| `stopConnection(sessionId)` | 取消两条通道、扫描、恢复与待办，返回后仍须保证晚到回调不能复活会话 |

### 5.3 核心/连接服务 → GUI

- `connectionSnapshotChanged(snapshot)`：带单调递增 `revision`；GUI 丢弃过期快照。
- `peerDiscovered(result)`：带操作 ID、传输类型及身份匹配可信度，名称匹配不能报告为已认证。
- `userActionRequired(action)` / `userActionResolved(actionId, result)`：动作只在对应会话有效。
- `operationFinished(result)`：说明操作完成或取消，不替代核心连接状态。
- `capabilitiesChanged(capabilities)`：蓝牙开关、权限、网卡、配对代理等变化。
- `diagnosticEvent(event)`：辅助日志，不驱动 GUI 通过解析自然语言推断状态。

建议通过现有本地 IPC 增加版本化结构载荷，保留原 `transportState` 通知的过渡兼容。消息必须限制大小、校验字段和枚举，不能从远端透传任意本地操作命令。

### 5.4 两端协商消息

至少包含：

1. `CapabilitiesOffer / CapabilitiesAccept`：协商版本、角色、通道能力、策略和功能限制。
2. `EndpointOffer / EndpointUpdate`：交换已认证会话内的有限端点及更新代次。
3. `BackupPrepare / BackupPrepared / BackupRejected`：约定监听/拨号责任、准备期限和原因。
4. `PolicyUpdate / PolicyAck`：反馈开关的实际协商结果，避免本端 UI 已关闭而对端仍补建。
5. `CancelOperation`：终止尚未完成的协商或准备，不能终止不属于该会话的任务。

所有控制消息必须经加密、已认证且绑定同一 Peer 的会话传输，带协议版本、会话实例和请求 ID。候选连接在身份认证前不能发送键鼠数据。

**协议设计前置项：** 当前普通网络连接、单蓝牙桥接和 `DFF1` 自动模式的握手并不相同。已确认不要求兼容旧客户端；优先统一当前版本网络与蓝牙的管理封装，首条连接从建立时即支持协商，不为兼容旧版额外维护入口。不能在已运行的输入流上未经协商更换帧格式。具体 wire format、发现入口和版本号须经技术评审锁定后再开发。

## 6. 状态模型与首页映射

使用相互独立的状态维度，避免组合成含义模糊的单一字符串：

- 首连/核心：`idle / connecting / awaitingTrust / connected / recovering / stopping / stopped / failed`。
- 每条通道：`unavailable / discovering / awaitingUser / connecting / authenticating / ready / active / retrying / closed`。
- 备用策略：`disabled / negotiating / preparing / ready / needsAction / unavailable / blockedByPeer / unsupported`。

“已就绪”是通过认证的热备用，未承载当前键鼠会话；“活动”还要求核心握手成功。网络或蓝牙系统状态独立展示。

| 场景 | 首页固定提示行 | 用户操作 |
|---|---|---|
| 主连接可用、正在补建 | 已连接局域网，正在准备蓝牙备用连接… | 可以继续使用 |
| 双通道就绪 | 当前使用局域网 · 蓝牙备用已就绪 | 可查看连接详情 |
| 初次权限/配对 | 当前连接正常 · 完成蓝牙配对即可启用备用连接 | 完成配对 / 稍后 |
| 蓝牙关闭或被拒绝 | 当前使用局域网 · 蓝牙备用暂不可用 | 打开设置 / 手动重试 |
| 蓝牙首连、无网络 | 当前使用蓝牙 · 局域网暂不可用 | 无需处理，变化后重试 |
| 对端关闭开关 | 当前连接正常 · 对方未启用备用连接 | 对方可自行开启 |
| 不兼容的对端 | 当前连接正常 · 对方版本暂不支持备用连接 | 查看版本信息 |
| 正在故障恢复 | 连接中断，正在通过蓝牙恢复… | 控制留在本机 |
| 恢复成功 | 已通过蓝牙恢复 · 移至屏幕边缘继续使用 | 正常跨屏 |
| 全部不可用 | 暂时无法连接，正在自动重试 | 可主动断开 |

首页开关显示本端请求状态，提示行显示实际生效状态。默认开启不能显示为“备用已就绪”。切换方式、开关或状态时不改变主按钮与卡片锚点；详细错误和配对内容在明确打开的详情区域展示。

## 7. 重试、性能与运行约束

以下是首版建议参数与验收目标，须以双机实测确认，不是已测得的性能承诺：

| 项目 | 要求/建议默认值 |
|---|---|
| GUI 响应 | 无同步蓝牙扫描、系统配对等待、网络探测或核心停止等待；使用异步状态反馈 |
| 首连 | 不等待备用准备完成；不满足备用条件仍可单通道启动 |
| 能力协商 | 建议 3 秒超时；超时降级，主连接不退出 |
| 蓝牙扫描/服务发现 | 各次最多 20 秒，支持取消；前台用户重试可以立即发起 |
| 系统配对 | 沿用最多 60 秒等待，用户可取消或稍后处理 |
| 单候选连接/认证 | 建议总计最多 10 秒；候选最多 8 个、并发最多 2 个，避免长队列阻塞 |
| 拨号重试 | 沿用 1/2/4/8 秒退避、最高 8 秒，可加小幅抖动；用户停止后立即取消后续重试 |
| 无目标的全量无线扫描 | 不按 1 秒退避持续扫；建议失败后至少冷却 60 秒，优先事件触发、定向探测和缓存 |
| 故障检测 | 沿用约 1 秒心跳、约 6 秒无响应判故障；明确断开立即触发，分别记录检测与重建耗时 |
| 通知 | 沿用约 1.2 秒合并窗口；快速恢复合并为结果，不为每次后台失败弹窗 |
| 休眠/唤醒 | 失效旧操作代次，按有效策略恢复；主动断开或关闭状态不能被唤醒事件重新启用 |

当前自动模式把剪贴板限制为最多 64 KiB，并保留用户更低的限制，但现有服务端实现为全局限制。已确认必须改为按 Peer 限制，或改造剪贴板传输策略；不能让选定 Peer 的备用功能降低其他普通局域网 Peer 的能力。新功能必须协商并展示有效限制；具体采用哪种实现及受保护 Peer 的上限尚待技术设计锁定。

## 8. 跨平台验收矩阵

每种组合均需交换角色，覆盖 Mac 提供键鼠与 Mac 接收键鼠；Mac ↔ Linux 不只验证其中一个方向。

| 组合 | 首连方式 | 必测路径 |
|---|---|---|
| Mac A → Mac B、Mac B → Mac A | 局域网 | 蓝牙首次授权/配对、自动补建、断网恢复 |
| Mac A → Mac B、Mac B → Mac A | 蓝牙 | 身份确认、自动补建网络、关闭蓝牙恢复 |
| Mac → Linux、Linux → Mac | 局域网 | BlueZ 发现/系统代理、双向配对动作、蓝牙备用及断网恢复 |
| Mac → Linux、Linux → Mac | 蓝牙 | RFCOMM/服务兼容、网络端点协商与备用、蓝牙故障恢复 |

Linux 发行版、BlueZ/Qt 版本、桌面环境及 X11/Wayland 分别记录。传输成功与实际输入控制成功分开验收；不能用 TCP 模拟通过代替无线、系统配对或真实键鼠测试。

### 8.1 自动化验收

- 单端点即可启动；未知备用地址、权限被拒绝、对方不支持时不终止首连。
- 首连身份与备用身份不匹配、同名设备、过期端点或旧证书均不能接管当前会话。
- 任意一端关闭开关、主动断开、取消配对、切换目标、GUI/核心重启及晚到回调的处理正确。
- 并发补建幂等，两个通道只有一个活动键鼠会话；错误与超时分属正确作用域。
- 控制帧超长、字段错误、重复请求、未知版本、旧代次和乱序事件均有确定处理。
- 备用错误不影响主通道；主通道故障后输入状态释放、无旧数据重放、恢复后需正常跨屏。
- 健康蓝牙不自动回切网络；网络恢复后成为备用。
- IPC 断开重连后快照一致；默认开关开启与实际备用就绪显示不同。
- 配置迁移、显式关闭保留、对端偏好不覆盖本端、剪贴板限制协商均有测试。
- 所有模式/连接状态下主按钮、卡片和下方标题保持对齐。

### 8.2 实机验收

- 每个矩阵条目完成至少 10 次故障恢复，覆盖主动关网络/蓝牙和静默丢包，记录失败率、检测耗时与恢复耗时。
- 两种平台组合各完成至少 2 小时持续键鼠运行，记录输入异常、卡键、断线和恢复；结果不能推断为更长时间的稳定性承诺。
- 测试睡眠唤醒、对端进程重启、地址变化、蓝牙权限拒绝/撤销、缺少 BlueZ 代理及距离导致的无线不可达。
- 故障发生在按键按下、拖动中和剪贴板传输中时，没有卡键、旧操作补发或指针自动回送。
- 首次需要的用户确认可完成、可拒绝、可取消；拒绝备用准备后首条连接仍可操作。
- 升级后的应用签名与系统授权连续性按现有打包要求验证，不能把权限失效误归因于通道故障。

## 9. 开发拆分与完成标准

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| A 技术验证 | 锁定协议兼容方案、Mac ↔ Linux 配对代理、服务发现与身份映射方案 | 两种首连方向的最小双机验证通过；不能只验证 Mac 本机 |
| B 核心能力 | Peer 模型、能力协商、端点交换、单通道启动、动态补建与取消 | 异常/并发/身份测试通过，备用失败不影响主连接 |
| C 编排与接口 | 有效策略、结构化状态、GUI IPC、持久化和旧配置迁移 | 开关语义、快照恢复、主动断开及重试行为通过 |
| D 首页接入 | 两种首连入口、默认开关、固定提示行、权限配对待办、设备状态 | UI 对齐/交互检查通过，不以模拟状态替代真实状态 |
| E 联调发布 | 上述矩阵、性能记录、签名包及说明 | 平台、剪贴板默认策略和全部 P0 验收完成 |

“完成”的最低标准：用户只手动建立首条连接；满足权限、配对、身份与可达条件后，另一条无需手动录入地址即可成为认证备用；故障后可以恢复，且停止/拒绝行为始终有效。

## 10. 已确认与待补充信息

### 已确认

- 首版支持 Mac ↔ Mac、Mac ↔ Linux。
- 用户只选择一种首连方式；另一种由两端自动协商建立。
- 使用一个默认开启的“自动建立备用连接”选项，同时提供故障自动恢复。
- 不要求兼容旧客户端，可统一协议与入口。
- 关闭自动备用后，当前通道自身继续自动重连；主动断开则停止该 Peer 全部重连。
- 剪贴板采用按 Peer 限制或调整传输策略，不能沿用全局限制影响其他 Peer。
- “断开连接”只断开选定 Peer，“停止共享”停止全部连接。

### 待用户补充，不阻塞文档评审

1. 两台 Mac 与 Linux 测试机的系统版本；Linux 发行版、桌面环境及 X11/Wayland，是否有实体机和可用蓝牙适配器。
2. 首版最常用的共享方向和设备数量；如有多设备局域网共享，哪一台需要蓝牙备用保护。
3. 受保护 Peer 的具体剪贴板上限，以及采用按 Peer 限制还是调整传输策略；已确定不得继续使用影响其他 Peer 的全局限制。

### 技术评审必须确认

- 不保留旧版兼容入口前提下，普通网络、单蓝牙、自动备用的统一管理封装与发现方式。
- 蓝牙服务定位在两种系统上的可获得性；无直接蓝牙地址时的可靠发现方式。
- Linux 的配对代理方案与实际输入控制环境，权限操作的执行进程和系统授权归属。
- 配置迁移规则、默认策略与有效剪贴板限制的最终发布选择。

上述尚未确认的项目必须作为开发任务和发布门槛跟踪，不得以“后台自动建立”文案掩盖实际需要的系统确认或不可达条件。
