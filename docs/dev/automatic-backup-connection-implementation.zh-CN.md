# 自动建立备用连接：开发实现记录

日期：2026-10-23。本文描述当前开发实现，配合需求 v0.2 阅读。真实 Mac ↔ Mac、Mac ↔ Linux 无线验收尚未完成；不要将自动化通过解释为发布验收通过。

## 使用方式

两端使用同一开发版本，保留原有角色、电脑名称、布局和通信证书。Mac/Linux 构建默认开启 `BUILD_BLUETOOTH`，需要 Qt Bluetooth 6.7+ 和 OpenSSL 3。辅助功能等输入权限沿用原实现；认证连接使用统一 DFF2 管理封装，不兼容早期实验客户端。

首页增加首连方式（局域网、蓝牙）和默认开启的自动备用选项。选择局域网时继续使用原网络地址。蓝牙首连时，共享端先选择蓝牙并开始共享，接收端查找电脑、选择蓝牙地址，再开始连接。发现结果只是线索，实际连接仍验证通信证书。

- 网络首连：身份和核心握手完成后交换能力、端点与策略，按蓝牙地址定向补建；地址未知时查询新服务并匹配运行实例，再用证书认证。
- 蓝牙首连：认证后交换网络地址与监听端口，优先 IPv4，再尝试其他有限候选；网络作为备用，不抢占正常的蓝牙。
- 每个候选的连接和认证有超时；最多保留 8 个网络候选，使用串行拨号和退避，不进行通用端口扫描。IPv6 link-local 的作用域根据本机网卡重新解析。
- 两端策略交集决定是否准备备用。已有单一 Peer 时可自动选择；多 Peer 且未明确选择时，需要点击“为此电脑启用备用”。只保护一个选定 Peer，其他网络 Peer 继续工作。
- 蓝牙权限、配对、确认码、PIN 等通过“完成设置”推进。可以稍后处理，首连保持工作；取消后的旧动作 ID 无效。Linux 使用系统配对代理，不提供伪造的应用内确认能力。
- 关闭备用：关闭未活动的备用通道及其任务，保留活动通道及其自身重连。断开选定电脑：停止该 Peer；停止共享：终止整个核心及全部 Peer。
- 主动断开的 Peer 不因后台重试自动复活。界面提供显式重新连接；若双方均停止，需要两端允许重新连接。
- 需要 TLS 和证书校验才能补建备用。关闭加密/身份校验时，原有普通网络行为保留，界面说明备用条件不足。

## 底层结构

`ConnectionManager` 管理统一 TCP/RFCOMM 入口、按 SHA256 身份的 Peer、端点、策略、配对动作、退避和快照。所有 Peer 共用一个现有键鼠核心，服务端核心仅监听回环地址，管理层向它提供多个独立连接。

`TlsChannel` 先验证已有信任；未知证书通过既有 GUI 信任流程确认后重试，未确认前不向核心转发输入。第二条通道固定为同一身份；已缓存网络目标/蓝牙地址的首连也会绑定已知 Peer，避免地址复用误连其他可信电脑。证书变化需要显式处理信任和关联，不静默替换。

`FailoverLink` 升级为 DFF2，支持有界管理载荷、版本、角色和运行实例校验。策略和端点在已认证链路上交换；端点有更新代次和短有效期。旧控制修订被忽略，新进程实例重新开始修订。协议握手、首次有效心跳以及核心握手分别记录，未完成时不会声称备用已就绪或核心已可用。

`FailoverSession` 继续负责单活动会话、激活 epoch、旧数据隔离与回压。初次连接保留用户选择，故障后两路都可用时优先网络，健康蓝牙不回切。控制回本机、合成输入释放和恢复提示沿用已有机制。

接收核心处理变慢时，逐层暂停管理帧和 TLS 明文读取，排队量回落后恢复；保留队列硬上限，避免正常大剪贴板突发直接挤爆接收队列。

通过流过滤器传递已验证的核心证书身份，核心完成/断开事件按 Peer 上报。其他客户端连接不会再误触发受保护 Peer 的恢复状态。

## 剪贴板

不再通过服务端 Config 全局施加自动模式的 64 KiB 限制。`PeerPolicy` 以已验证身份施加单 Peer 上限，发送、接收和排队发送都检查，保留原有更低限制；其他 Peer 不受这一上限影响。

剪贴板发送分块新增仅存在于本地事件队列的会话代次。旧代理地址被复用时，旧分块仍不能发送到新会话；线上分块格式不变。恢复时不重放旧通道缓存，重新跨屏后仍可按正常规则同步当前剪贴板。

## 状态、权限和持久化

本地 IPC 增加结构化快照和动作命令，保留旧通知字符串用于现有提示策略。接收端缓存半包、处理粘包、限制 64 KiB 消息，认证握手前不能执行控制命令。Mac/Linux 桌面核心 socket 限制为当前用户访问；新增控制接口不面向其他本地用户。此权限边界意味着以 root 运行核心的旧服务模式不属于本次桌面路径验证范围。

完整快照可在 IPC 握手后恢复，包含 revision、Peer、各通道、重试时间、有效策略、动作及原因；管理载荷和 PIN 不写入 IPC 详细日志。

旧 `autoFailover` 只有实际存在时才迁移；明确关闭保留，新配置继承默认开启。Peer 策略、名称、蓝牙关联、认证端点及验证时间保存到 `connection/peers`；显式备用目标保存到 `connection/backupTarget`。不根据对端关闭覆盖本端偏好。

信任库变化会重新检查并停止被撤销 Peer，删除应用内关联，不删除系统蓝牙配对。睡眠时取消配对/扫描并关闭旧链路；唤醒后按有效策略重连，已停止 Peer 不恢复。

macOS 蓝牙开关/可发现性仍受系统限制，软件不能替用户自动开启。网络备用还受本地网络隐私权限、服务端防火墙、AP 隔离和路由影响。通知授权仅影响横幅，不作为传输启动条件。

## 自动化与待验收

2026-10-23：Mac arm64 开发构建成功，12 个回归测试目标全部通过（37.46 秒）：ServerProxyTests、ClipboardChunksTests、SettingsTests、InputReleaseTests、TransportIpcTests、DeviceListPageTests、MainWindowHomeTests、TransportNotificationsTests、FailoverTests、ConnectionManagerTests、ServerTests、ClientProxyTests。

测试覆盖真实 TLS/TCP、以 TCP 字节流替代 RFCOMM 的双通道逻辑：

- 单端点首连，备用权限拒绝不影响活动连接；蓝牙首连后学习网络地址。
- 动态备用就绪，关闭策略保留主路，关闭后原通道仍重连。
- 蓝牙失效后恢复到已学习网络，恢复不主动抢占健康蓝牙。
- 多 Peer 独立运行及单 Peer 停止；取消旧动作无效，停止后睡眠唤醒不复活。
- TLS 错误指纹、异常帧、旧激活代次和心跳超时（沿用 FailoverTests）。
- IPC 认证、半包/粘包、超大消息；显式关闭迁移；按 Peer 限制与更低限制。
- 剪贴板代理对象地址复用时拒绝旧会话排队分块。
- 双向 2 MB 二进制传输，包括接收缓冲暂时限制为 1 字节后恢复，验证回压与数据完整性。
- 首页、设备页、通知、输入释放与既有核心协议回归。

仍需实机验收：两种平台组合交换角色；真实 SDP 发现、双方授权与配对、Linux BlueZ 系统代理、X11/Wayland 输入权限、无线距离/丢包/休眠、延迟与持续运行。无法扫描定位时提供地址选择兜底，不能把名称相同视为同一身份。当前开发环境没有完成上述无线矩阵，不提供已验证的延迟或恢复成功率。

未编译蓝牙的构建不提供本次统一连接功能；本次交付与验证以启用蓝牙的 Mac 开发包为准。Linux 服务代理缺失的精确错误分类和系统交互仍需实际环境核查，不据 Qt 的通用 PairingError 声称已识别其具体原因。
