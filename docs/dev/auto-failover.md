# 自动主备连接初版

目标是断线后自动恢复，不需要用户重新选择网络或蓝牙。允许短暂中断，切换会新建 Deskflow/TLS 会话。
本版本仍按当前任务范围仅做 Mac 开发和本机验证，未进行 Linux 硬件联调。

## 已实现的行为

- 网络 TCP 和蓝牙 RFCOMM 各自保持已认证的待命连接，每秒健康探测；连续约 6 秒没有有效心跳响应会关闭故障通道，明确断开则立即处理。
- 两条通道都就绪时优先网络，只有一条能转发键鼠会话；备用通道损坏不会中断当前控制。
- 主通道损坏时关闭本机核心连接，丢弃旧数据，清理合成按键和鼠标按钮；既有客户端自动重连后选择可用备用通道，重新建立核心 TLS 会话。
- 断线后控制回到本机；恢复后正常跨屏即可继续。不会续接拖动、恢复旧点击或自动把光标送回远端。
- 网络恢复后作为备用保留，不主动从正常的蓝牙切回，避免反复切换。这是初版的保守取舍。
- 两条都不可用时后台重试，间隔按 1/2/4/8 秒递增，上限 8 秒；不会重复弹出每次重试的通知。
- 切换通知延迟约 1.2 秒，快速恢复只提示恢复结果；持续失败提示自动重试；成功提示只在核心握手完成并短暂稳定后显示。状态栏/托盘保留当前状态，通知不要求点击确认。
- 自动模式统一将剪贴板限制为最多 64 KiB，保留用户原本更低的上限；不修改用户保存的大小。较大的文本或图片会被跳过。

## 安全和会话边界

两条待命连接都使用 OpenSSL 双向 TLS，并固定为同一份已信任的对端 SHA256 证书指纹。
蓝牙地址只用于连接和初步白名单过滤，不作为身份凭证。原有核心 TLS 和指纹校验继续保留。
因此此版本在两端核心外增加了一层用于认证待命/切换控制消息的 TLS。

固定服务 UUID 为 `28d88531-5adc-4852-bf1c-2bc9107c315e`，与旧单通道蓝牙原型分开。
同一核心进程的两条通道使用相同实例标识；客户端是激活操作的唯一发起方。
单调递增的会话代次用于拒绝旧激活、旧关闭和旧数据，确保旧回调不能接管新会话。
每次切换都关闭旧核心连接，没有跨会话输入重放或未确认数据补发。

收发队列有界，核心输入会被回压。旧缓存不会在恢复后集中发送。
同一 TLS 会话跨路径保活、带宽聚合、多个远端、自动回切及大剪贴板调度均不属于本版本范围。

## 启用方式

需要两端都使用支持本协议的版本，根项目构建启用 `-DBUILD_BLUETOOTH=ON`。
默认自动模式关闭，普通 TCP 网络模式继续沿用原有逻辑。

先通过原来的网络连接完成电脑布局和双向证书信任，并在系统中完成蓝牙配对。
停止旧版本 Deskflow 后，在两端现有设置文件中增加以下内容，随后启动本版本：

```ini
[connection]
autoFailover=true
bluetoothPeer=AA:BB:CC:DD:EE:FF
peerFingerprint=对端证书的64位SHA256十六进制指纹
```

`bluetoothPeer` 是另一台电脑的蓝牙地址；两台电脑填写的值不同。
`peerFingerprint` 必须已存在于本机对应的 `trusted-servers`（客户端）或 `trusted-clients`（服务端）指纹库中。
如果该指纹库仅有一条 SHA256 身份，可以省略 `peerFingerprint`；多条时必须明确指定，避免连接错误设备。
不能省略 TLS 或关闭证书检查；身份、证书文件或配置不正确时会拒绝启动。

Mac 默认设置文件是 `~/Library/Deskflow/Deskflow.conf`。GUI 从该文件读取自动模式，不需要每次手动选择。
本版未新增设置表单，首次配置仍需编辑设置文件；不要同时运行旧版本，否则旧版本可能清理不认识的设置项。

客户端原有 `[client] remoteHost` 保留网络主机地址，初版只接受一个主机；`[core] port` 为两端网络端口，默认 24800。
服务端原有 `[core] interface` 可为空（监听所有接口），填写时须是数字 IP。
本模式关闭普通 mDNS 广播，避免旧版本误把自动模式端口当作普通 Deskflow 服务连接。

命令行也可显式启用，其他布局、网络地址和证书设置仍读取现有配置：

```sh
"$CORE" server --auto-failover --bluetooth-peer AA:BB:CC:DD:EE:FF
"$CORE" client --auto-failover --bluetooth-peer 11:22:33:44:55:66
```

服务端内部核心端口通过本机临时端口分配，仅回环监听；对外端口由自动传输层监听。
旧核心接口要求临时端口释放后再绑定；若绑定失败，按原有核心启动失败流程退出，不会回退到不安全地址。
初版不支持修改自动模式配置后的热应用，需要重启核心。

## 实现入口

- `src/lib/net/bluetooth/TlsChannel.*`：OpenSSL 内存 BIO，支持 TCP 和 RFCOMM，证书固定、握手超时、有界缓冲。
- `FailoverLink.*`：版本握手、心跳、控制/数据帧。
- `FailoverSession.*`：单一活动会话、主备选择、代次隔离、核心断开与重新激活。
- `AutoTransport.*`：实际 TCP/RFCOMM 监听、拨号和后台重试。
- `src/lib/gui/core/TransportNotifications.*`：轻量通知合并和去重策略。
- `src/lib/deskflow/Computer.*`：离开/禁用远端时清理合成输入和按住的鼠标按钮。

## 验证边界

自动化覆盖真实 TLS 认证与错误指纹拒绝、待命不创建控制会话、网络优先、双向二进制传输、主路失效后新建备用会话、旧代次拒绝、备用故障隔离、网络恢复不回切、全部断开、黑洞心跳超时、异常帧拒绝，以及实际 TCP 连接器在对端重启后的自动重连。
输入测试覆盖拖动按钮释放、正常释放不重复、禁止正常离开时仍清理、保留主机物理输入。
通知测试覆盖快速恢复合并、持续失败不刷屏、停止后取消待发通知。

这些测试使用本机 TCP 字节流替代蓝牙无线链路。真实 Mac/Linux 配对、断网/关蓝牙、休眠和远端键鼠体验仍需两机联调；不能把本机通过视为无线环境稳定性已经验证。
