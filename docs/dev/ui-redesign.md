## 模式切换点击范围与原生列表修复（2026-10-22）

排查“切换要等几秒”时确认 HomeModeButton 只重写绘制，没有重写 QRadioButton::hitButton。绘制内容在整块分段中居中，但默认命中范围仍由原生单选按钮样式计算。隔离配置诊断中，309×40 的接收模式按钮在横向 80% 和 95% 处点击完全未选中，共享按钮 95% 处也未选中；有效命中后切换调用约 1–4 ms。该结果证明存在漏接点击，不能将这些漏接视为实际等待数秒，也不能排除不同运行状态下的其他耗时。

重写 hitButton，使整个可见分段响应点击。中英文、886/1060 宽度的左右边缘、中心及上下边缘均加入真实鼠标事件回归。连续原生无障碍操作还复现了首页 QListWidget::clear 对应的 QMacAccessibilityElement::dealloc 崩溃（17:29:11 两份报告）。首页设备卡改为可访问 List 容器加真实按钮子项，沿用设备列表页已有方案，保留键盘/VoiceOver 操作及原卡片绘制，避免 Cocoa 合成表格行在清空模型时失效。

22 项首页检查通过。证书签名更新后，实机连续 20 次切换全部选中成功，无崩溃；自动化点击及读取状态往返 391–453 ms（包含外部工具通信，不是单独的业务切换耗时）。随后使用真实坐标点击两个分段右侧空白区，均立即切换成功；恢复原接收模式。更新后辅助功能授权仍保留。预览包仍为 `dist/BMouse-Home-Preview-macos-arm64.zip`。

## 设备列表落地（2026-10-22）

按确认的三栏原型新增 `DeviceListPage`，复用主导航、顶部工具栏与页面容器；首页“全部设备”、设备卡片及“查找共享端”进入该页。中栏搜索、状态筛选、可折叠分组与右侧详情均使用 Qt Widgets，不再通过旧发现对话框浏览设备。

设备数据合并本机、内部排列配置、真实接收端连接、连接历史、已保存共享端及 mDNS 快照。按标准化的地址和端口合并共享端；设备名称、用途和状态分开保存，不根据历史或发现结果推断已连接。旧历史缺少角色信息时仅显示连接记录，不自动当成可连接共享端。未获取到的对端地址显示“尚未获取”，不推测操作系统。

添加接收端进入屏幕排列的草稿，并定位已有电脑或预填新电脑名称；添加共享端仅保存本地记录。连接操作进入现有模式切换和核心启动/重启流程，保留自动连接选择、权限检查及证书核对。共享端详情的屏幕排列入口禁用并提示在共享端操作；其设置入口打开本机接收端设置。接收端设备设置定位到现有按键映射与边角设置；诊断进入实际日志。新增 KnownServers、RecentServers 状态元数据，核心设置清理器识别这些键。

mDNS 刷新通过线程安全请求触发下一轮查询；浏览线程异常退出后可再次刷新，主窗口销毁前主动停止并等待，避免派生类销毁后的回调。

macOS 原生检查曾复现 Qt Cocoa 辅助功能合成表格行在动态刷新时的释放崩溃。设备列表改为提供真实可访问按钮行，保留列表绘制、按键与读屏操作；在插入任何设备之前替换构造阶段提前缓存的表格接口。搜索刷新后保留输入焦点，避免新建行控件抢走连续输入。新增接口与键盘输入回归测试。最终本地签名包已实际启动，完成搜索、清空、设备选择与进入对应电脑设置检查，没有修改本机键鼠配置或启动控制服务。七组 GUI/配置/网络测试及 mDNS 生命周期测试通过，签名和压缩包完整性校验通过。
