# 设备详情：用途与连接信息

日期：2026-10-26。

右侧设备详情保留设备名称、状态、输入角色及来源，移除重复的电脑名称和资料行，增加「当前用途」「连接信息」。首页和连接、模式切换操作不变。界面不使用主用或备用标签。

## 展示规则

- 当前用途分别列出键鼠共享、扩展屏幕。键鼠只在用途服务确认 InputActive 且通道 active 时显示「IP 网络 / 蓝牙 · 使用中」。通道已连接本身不能证明业务正在使用。
- 扩展模式显示原键鼠共享「已暂停」。只有用途 effectiveMode=extended、相同认证设备的显示快照 Streaming 且 firstFramePresented=true，才显示「IP 网络 · 显示中」。等待和切换过程不显示成功。
- 网络、蓝牙独立显示已连接、正在连接、正在认证、正在重连、未连接或状态待确认。active 与 ready 在连接层均显示「已连接」，用途行解释业务归属。
- 扩展媒体是独立的 IP 连接；真实呈现的媒体也构成网络已连接，不能仅凭键鼠网络 lane 不可用就说整个网络未连接。
- 地址优先取通道真实 remoteAddress；没有上报时明确标记「地址尚未上报」。现有保存的网络地址仅标记「保存地址」，不冒充实际连接端点。长地址省略，悬停和辅助功能保留全文。
- 延迟显示应用往返时间 RTT；速率显示应用发送与接收速率，不叫最大可用带宽。没有测量、无效测量或超过 5 秒的旧样本显示 —，测得空闲速率才显示 0。
- 原核心停止或重新启动时清除通道缓存和修订号；断线或连接归属变化时清除旧设备通道状态。数据按认证 peerId 绑定，不按名字匹配。

实际网络/蓝牙地址已增加到 ConnectionManager 通道快照，来自完成认证的真实 socket；通道失效后不继续公布旧端点。媒体端点与键鼠端点是独立连接，不将键鼠端口解释为媒体端口。

## 现有接口与待补指标

`CoreProcess::transportSnapshot` → `PeerUsageModel::receiveTransportSnapshot` 使用现有 version=2、revision、peers[].peerId、channels[].type/state。

`PeerUsageService` 提供 effectiveMode 等用途状态；`DisplayService` 提供 peerId/state/firstFramePresented，均已接入视图。更新只修改控件内容，不重建设备详情列表或重置滚动位置。

当前产品通道快照没有完整 RTT、吞吐测量；本次不会主动测速，也不会把系统链路标称速率、视频目标帧率或历史日志当作测量。

为启用指标，通道生产者需提供以下可选字段：

| 字段 | 含义 |
| --- | --- |
| remoteAddress | 实际对端网络端点或蓝牙地址 |
| rttMs | 有限非负数，应用通道 RTT，毫秒 |
| txBytesPerSecond / rxBytesPerSecond | 有限非负数，当前采样窗口的发送/接收字节速率 |
| sampledAtMs | 核心本机 Unix 毫秒时间，十进制字符串 |
| metricsFresh | 此样本有效；GUI 仍独立检查 5 秒过期 |

显示画面时网络指标读取当前 DisplayService.statistics 中的同名字段，避免把少量键鼠控制流量冒充视频流量。字段缺失时保持 —。如后续要显示整台设备的汇总网络流量，需要单独的按业务汇总契约和去重规则，不能直接混用两条链路统计。

通道故障原因可通过连接状态提示查看；字段目前仅有 peer 级 reason，后续应补齐每通道 reasonCode/errorText，避免把某一通道错误归给另一通道。

## 验证重点

双通道已连接只标连接状态；键鼠实际通道切换同步更新用途行；扩展首帧前不激活；另一设备的呈现事件不能污染当前设备；独立媒体连接不与键鼠通道状态矛盾；断线清空旧信息；缺失与过期样本为 —；真实零速率为 0。
