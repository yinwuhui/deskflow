# M014：Mac 显示拓扑探测进程隔离

2026-10-28。对应架构第 4、11、12、22、26 节；这是受监督探测的一个阶段，不代表全部超时路径已经认证。

MacResourceProvider 的 snapshot/inspect 不再直接在资源线程调用 CoreGraphics 显示枚举及桌面锁状态检查。已注册且 SHA256/所有者/权限校验的同一 Mac helper 可执行 `--display-platform-probe`，在独立 QProcess 内读取状态，并返回受 64 KiB、64 个显示器和字段范围限制的数据。异常退出、期限到达、数据不完整或超限均返回未知，不能据此关闭资源 owner。等待超过期限时只终止自己启动的探测子进程，并等待最多额外 1 秒回收；这不是无额外耗时的硬实时保证。

Mac 真机运行 M013 手动资源测试的 ambiguous、normal、recover、intent 四种场景均通过，包含实际输出创建/清理和账本重开。新增 probe-timeout 模式用本测试可执行文件模拟探测卡住 5 秒，调用方 300ms 截止后返回不完整，受控测试通过。它是探测进程故障模拟，不是 WindowServer 真机卡死测试；这些验证不涉及媒体和跨机呈现。

公共监督器新增只读 `validWorkerExecutable` 包装，复用原有注册校验；未放宽可执行文件策略。原有产品入口没有切换到新 provider。探测启动前同步读取/哈希可执行文件和 QProcess 启动本身仍可能被系统 I/O 阻塞；二进制结果目前来自可信已校验 helper，后续还需独立加强消息解码前的长度防护及供应链/可执行文件替换竞态防护，不能宣称完整超时和安全认证。Mac 私有 API、父进程崩溃、全系统睡眠及 Windows 未认证等既有边界继续有效。

代码、手动测试及备忘录同阶段提交；通过 `git log --follow -- <本文件>` 定位。Mac/Ubuntu 公共监督器各 6/6 相关真实子进程回归通过（Mac 10.30 秒、Ubuntu 11.24 秒）；Mac 原生模块不在 Linux 编译。
