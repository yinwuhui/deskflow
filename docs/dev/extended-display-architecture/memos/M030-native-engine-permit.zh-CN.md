# M030：原生媒体引擎许可接入

## 边界与设计对应

将 M029 的本地媒体许可接入 M023 开发引擎，对应媒体工作绑定会话/计划/来源以及撤销停止约束。不是生产授权 broker、真实设备认证或隔离 Worker 的完成证明。诊断回环在完成控制 nonce 绑定后显式签发 30 秒许可；独立政策夹具也显式签发。

## 实现与不变量

- NativeWebRtcConfiguration 复用完整 MediaWorkContext，prepare 在创建管线前要求许可存在、有效且完整匹配。使用纯结构 validWorkerBinding，不再构造伪 secret 的 WorkerProtocol 做结构检查。
- start、submit、信令/帧关联输入、解码帧获取、关键帧请求、信令/关联输出均检查许可。
- 信令回调、编码探针、RTP 探针、解码采样与待发布帧再次检查许可。实际 WebRTC 元素的安全配置不因许可失效而跳过。
- owner poll 观察到失效后记录 MediaPermitInactive 并走既有 stop。stop/stopped 不需要许可；已借出解码帧继续持有内存，释放前不能声称停止完成。
- 撤销是原子准入屏障，检查前已接纳的工作可能仍在途；检查与 SDK 调用间不提供全局事务。现有网络缓冲、重传及原生状态转换需进程监督器的外部期限，本模块不承诺撤销瞬间零网络包。

## 验证

两端政策夹具增加缺失许可、已撤销许可、绑定改变三项。真实本机 8 秒媒体回环持有有效输入及解码帧，在主动撤销后检查新工作被拒、poll 停止、持有解码租约阻止完成、最终预算回零。具体统计及桌面复测结果含失败日志见 M030-test-results.json。

## 已知限制与未接入项

MacCaptureSource 尚未关联此许可；其现有资源撤销规则仍独立生效。开发桌面样机的控制回环仅授权引擎部分，不能宣称整条采集链路已受同一许可约束。生产 owner/输入屏障、独立媒体进程、实际 TLS/设备认证、双机及 Windows 编译认证仍未完成。测试不构成长时性能、总内存或 30fps 认证。
